## Decided

### Product

- Clean rewrite on the orphan branch `pali`; **`main` since 2026-09-16 20:10** (GitHub rename: v1's `main` became `v1`, `pali` was pushed as `main` and made the default; the old `pali` ref stays until the marko clone is switched). v1 is branch `v1`, checked out at `~/proj/pal-v1`; its tags `v0.1.2`..`v0.2.1` remain.
- Name is `pal`; `pali` is the iteration. A standalone app people download, macOS and Linux. Raycast and Spotlight are the behaviour references; the visual identity is ours.
- Bar: high polish everywhere, no corners cut, minute UX details thought through.
- Root search: one box across everything; palettes are sections and drill-downs, not a root that lists palettes.
- Extensibility, one way: every palette including every default is an extension against the same API, no native tier. In-app code is shell (root search, action panel, settings, store, first run) plus OS capabilities as APIs (clipboard, windows, apps, files, hotkeys).
- Order of work: UI first (brief, component set, keyboard grammar), then protocol and host. Done in that order (`git log`).
- The pit board (pit.cagdas.io) holds Raycast research; its `in` lane is "relevant", never a commitment. Decisions are made here.

Nothing migrated.

Restored order `pal/palettes`, `apps`, then by name, so a cold frecency profile still leads with palettes and apps.
- `ttl` is palette meta (seconds; palette object, manifest `palettes.<key>.ttl`, `scripts` maps v1 `ttl` else its own setting). On `extension/loaded`: no `ttl` = list now; younger than `ttl` = keep restored rows; else one sequential pass 1 s after `host/ready` (`refresh_expired`). `live` still re-lists on show (within the budget under Core). `SourceInfo.stale` = listing pending: footer "updating…" + search sweep. `index_refresh(source?)` / `pal:refresh` (cmd+r) force past `ttl`, the `list` carries `refresh: true` so an extension's own cache steps aside.

### Core

- Matching in Rust: corpus in the core, `nucleo-matcher` single-thread, per-field scoring (name 100%, keyword 80%, subtitle 50%), top 200 to the webview, frecency hook before the top-N select. Numbers and why: `notes/matching.md`. Wired in 92dc234.
- Windows and system commands are core capabilities (`pal_core::windows`, `pal_core::system`; `core/windows.{list,close,minimize}`, `core/system.{commands,run}`), the `windows`/`system` extensions thin over them. Focus is a pick effect (`{ focus: id }`, effects.rs), like `paste`: the panel hides first so orderOut hands key focus back. `system.run` hides the panel itself.
- Accessibility in `pal_core::ax` (`trusted`/`request`, `AXUIElement` wrapper); the `accessibility_blocked` toast in effects.rs is paste's, the system prompt (`ax::request`) is shown once per run across paste and focus.
- Focus without Accessibility activates rather than refuses: `pal_core::windows::activate(id)` brings the window's app forward (app-level, no AX needed; `focus` reuses it after its AX raise) and returns the app's name; effects.rs hides the panel, activates, and once per run shows the HUD "Switched to <app>; per-window switching needs Accessibility" plus the system prompt. A toast cannot carry that message: the activation makes the panel resign key, which hides it (`panel/macos.rs`). With the permission nothing changed. The decision path is `focus_feedback` (unit-tested); Linux is unaffected (`ax::trusted()` is always true there).
- macOS window list: CoreGraphics (ids, order, bounds, on-screen) matched to AX windows by frame and title; titles from AX (CG needs Screen Recording for other apps' titles); an app answering AX with no windows falls back to CG rows; AX asked per app in parallel (10-30 ms when it naps).
- Linux backends detected, not configured: Hyprland (`hyprctl` + instance signature, newest `$XDG_RUNTIME_DIR/hypr/*` when the env var is missing), Sway (`SWAYSOCK`), X11 (`DISPLAY` + `wmctrl`). Hyprland has no minimise: parked on `special:minimized`, `focus` brings it back.
- Clipboard retention has one meaning (fcb967a): `max_age_days = 0` = no age limit; `exclude_apps` default in the manifest, so an explicit `[]` no longer drops the Keychain/Passwords protection.
- Exact name over history (`index::EXACT_BONUS = 1000`): an item whose trimmed name, or a keyword (alias), equals the trimmed query case-insensitively (no accent folding) gets +1000 after boost, before the top-N select; among exact hits score (with boost) then name length still order. Sized against the frecency maximum of 200 (`MAX_SCORE * BOOST_SCALE`) plus the fuzzy-vs-keyword-exact spread (nucleo ~16 per char, a keyword hit is 80% of a name hit: 33 apart at `chrome`); the welcome source's 1e9 is on the empty query only, where nothing is exact. Fixture corpus, frecency max on the other item: `ha` was harp 262 / ha 62, now ha 1062 / harp 262; `slack` with `snowflake_check` +200: Slack 1140 first. Cost: `ha` median 520 us, `chrome` 302 us (was 432 / 310). Trade-off, measured: `chrome` puts the nerd icon `chrome` (1166) above a hot Google Chrome (366) that used to lead at +30; `google chrome` or a keyword `chrome` on the app is the way back. No prefix bonus: nucleo scores prefix, word-start and exact alike (`ha`, `hat`, `Claude Code URL Handler` all 62), so a bonus that mattered against a boost would have to be at least the boost, which is the case frecency is designed to win (`term` with `terminal_tmux` +200 stays boosted-first); the length tie-break orders equals.
- `scripts` `ttl` setting defaults to 3600: no v1 plugin on hornet declares one, so every script ran on every start. A table's own `ttl` wins; a `live` table without one is exempt (a `ttl` now skips the show relist, and `otp` reads the Messages db for the current code); one resolved value feeds both the core's across-restarts keep and the extension's in-process cache. Bundled TypeScript extensions keep "no `ttl` = list on load": they are cheap (`docs/extensions.md`).
- Window layouts (`pal_core::windows::layout`, `windows::apply`; `core/windows.{frame,set_frame,displays,focused,layout}`; the `layout` pick effect in effects.rs; `extensions/window-management`): Raycast's set as one static row per layout. The arithmetic is pure and unit-tested on a 1440x900 visible frame and a two-display case; the OS part is `frame`/`set_frame` (macOS `AXPosition`/`AXSize`, the displays from `NSScreen` `frame`/`visibleFrame` flipped into the CG space, called off the main thread the way tao does; Hyprland `movewindowpixel exact`/`resizewindowpixel exact` after `setfloating` on a tiled window, `monitors -j` minus `reserved`; Sway and X11 written to the tools' documented shapes, fixture-tested only) and `focused` (frontmost app's `AXFocusedWindow`, `hyprctl activewindow`). The effect hides the panel first so the focused window is the one behind it, then the HUD names the layout or the refusal. `restore` is per window, in memory, and goes back to the frame before a *run* of pal layouts (a hand move in between starts a new run; `original_of`, unit-tested). Verified with the example binary on hornet (a hidden TextEdit document: seven layouts, restore, gap 10, frames read back exactly) and on marko (a spawned kitty over Hyprland, the focused path included). `palettes.<id>.item_hotkeys = { left_half = "ctrl+alt+left" }` registers per-item global hotkeys that run `index::run_pick` with the panel down (hotkey.rs `Target::Item`; root beats palette beats item in a clash); config-only, not in the Settings table.
- Live relist budget (`index::relist_due`, `LIVE_RELIST_GAP = 2 s`): on show, a live palette whose last show relist was issued under 2 s ago is skipped (double toggle, or a relist still in flight under the 2 s `LIVE_RELIST_TIMEOUT`), and one with a `ttl` relists only once its rows are older than that; no `ttl` = every show, as before. Parallel relist and the 2 s timeout unchanged; skipped palettes are logged (`index\tshow relist\tskipped ...`).

### Extensions and protocol

- Extensions are TypeScript in one Bun host, UI as a render tree from a fixed component set, never HTML. Scripts/data files stay the zero-code tier under the built-in `scripts` extension (runs v1 script plugins and data palettes from a v1 config). Raycast API compatibility: nice to have; keep the component set close enough that a shim stays plausible.
- Manifest is `pal.json` next to `index.ts`, readable without running code (Settings lists an extension whose code fails; host sends the manifest with `extension/error`). Shape (`host/src/protocol.ts` `Manifest`): `name title description version icon author repo`, `settings: SettingSpec[]` (`[extensions.<name>]`), `palettes.<key>.{settings,ttl,title}` (`[palettes.<id>].settings`; title only a fallback while it fails). Settings come from the manifest only (9332904).
- Palette id in the file: the extension's name when the palette is named like it (`emoji`, `apps`), else `<extension>-<palette>` (`clipboard-history`); bare keys, `index::palette_id` resolves.
- Settings reach extensions resolved: core overlays file over manifest defaults (`Config::extension_settings`/`palette_settings`, one level deep, a set key replaces the default whole), pushes `settings/changed` before the first `list` and on every change; `settings.get()` reads it. Caller identity: host async context in `list`/`pick`, file on the stack at import, explicit argument elsewhere (Bun drops context through dynamic import). Changed values relist. `secret` settings arrive resolved (fcb967a).
- `list`/`pick`/`detail` take a trailing `ctx: { filter?, args?, refresh? }`; on the wire `filter`/`args` ride flat.
- Lazy detail: palette method `detail(id, ctx)`, meta `detail: "lazy"`; the open-with-pane flag is `showDetail`. UI asks after 100 ms cursor rest on an item without inline markdown (`Item.lazyDetail`), merges the reply over the inline one, skeleton only past 150 ms more, drops replies for a left item. Host caches per palette+id until relist/reload, UI per level until the index changes. `scripts` runs v1 `preview` there, `preview_max` (default 4): `prs` lists in ~40 ms instead of ~5.9 s, one `gh pr view` per rest (~1 s, cached).
- The root has no scope dropdown (2026-09-16): a palette is picked from the list, the dropdown at the right of the search box was clutter. The dropdown is only a palette's own filters.
- Filters through the core: `PaletteMeta.filters` via `sources()`; Search dropdown, Tab cycles, first is default (core sends `filter: filters[0].id` explicitly). Indexed palette listed per filter (`index::filter`), bucket swapped, each filter's list kept until relist; root sees the filtered bucket while inside, reset to the first on leaving, the next query restores it; the page asks per query and the core no-ops when the bucket already holds that filter. Input palettes get it per keystroke. Verified with `scripts/otp` (4), `ha-states` (10).
- Drill-in: `Effect.push { extension, palette, args? }` pushes a scoped level; with `args` it lists from the extension per keystroke (never the index) and picks are not remembered (frecency is the parent's). `Effect.show: Detail & { title? }` pushes a detail-only level (full width, crumb, Back on Enter/Escape, arrows/PageUp/Down scroll, input read-only). `scripts` maps v1 `{palette, env}` to `push` (env as args, re-exported to the script; rows kept per args so a root pick still works after a drill-in listing) and v1 `show` to `show`.
- `keep` relists an indexed palette (`index::pick`): "stay open and list again" holds for every palette; a closed window is gone next query.
- Live at the root: a `live` non-`input` palette (windows, otp) is indexed and relisted on every `pal://shown` (`index::on_shown`), all at once, 2 s each, one `pal://index`, spawned after the event: paint stayed 1-4 ms; relist ~15-20 ms windows, ~300 ms otp (reads the Messages db); a timeout keeps old rows. `windows` is plain `live` so titles are root results; `system` stays `input: true` (keep-awake row flips), so its rows are not at the root.
- Picks from live and input palettes are not remembered (edc1670).
- `ssh` and `processes` (v1's builtins `ssh`/`psg`) and `files` (mdfind / fd / locate / find) are real extensions (708abf7, c8f478f); the v1 rows under `scripts` for them are gone.
- Palette rows carry the extension title as subtitle (Raycast does), omitted when equal to the palette title (Windows / Windows). Root sections ordered by best hit.
- View level (third protocol pass, driven by `extensions/blackjack`): `Palette.view(ctx)` in place of `list` makes a view palette (`PaletteMeta.view = "view"`, reported `input: true` so the core indexes nothing and the root keeps its row), and `Effect.view` carries a `View { tree, actions, title?, id?, keys?: "actions" }`. The tree is a fixed vocabulary the app draws with the tokens (`ViewNode`: `stack`, `text`, `image` (`icon://` or `data:image/` only), `badge`, `divider`, `spacer`, `progress`, `keycap`), never HTML; unknown node types are skipped by the renderer, not thrown on. Keyed nodes get entrances/exits through the presence wrapper (`Transition { enter: fade|slide-up|flip, exit: fade|none, delay: 0..8 steps of --pal-dur-fast }`); a card is not a primitive, blackjack draws its cards as SVG data urls (`cards.ts`). The Launcher pushes a `{ kind: "view" }` level: no search input (the view's title in its place, `Search title=`), the footer keeps the first action and ⌘K, Escape/⌘⌫ pop, Enter/⌘Enter are actions 0/1, a modifier combo its action; with `keys: "actions"` a bare key (`h`, `space`, `+`, `up`) runs the action carrying it. A pick is `pick(view.id ?? "view", action, ctx)`; `{ view }` back replaces the level's tree in place (from a list row it pushes a level). The host checks every view (`host/src/view.ts`): `pal:` action ids refused, 2000 nodes / 24 deep, duplicate sibling keys. `docs/extensions.md`.
- Form level (`Effect.form`, driven by `extensions/quicklinks` and `extensions/snippets`): `Form { id?, title, fields: FormField[], submit: { id, title }, cancel?, errors? }`, fields `text|textarea|password|select|checkbox` with `label placeholder default required description`. The Launcher pushes `{ kind: "form" }` (the `Form` component in the body, the title in the search row as for a view, the submit in the footer, no ⌘K); Enter submits as `pick(form.id ?? row.id, submit.id, ctx)` with `ctx.values` (on the wire `values` rides flat beside `args`; `index::pick` takes `values: Option<Value>`), `required` is checked in the panel first (field marked and focused, no pick). A `{ form }` answer to the submit replaces the spec in place (the fields keep what was typed, `errors` show under them); any other answer pops the form first. `checkForm` in `host/src/view.ts` refuses empty/duplicate fields, unknown kinds, a `pal:` submit id, errors for no field. `stays_open` in effects.rs does not list `form` yet (only matters for a `copy` sent with a form: the HUD would say Copied). `ctxOf` now drops a `null` `args` (the core sends `args: null` for a plain level; extensions only ever truth-tested it). Vitest interaction tests run under `happy-dom` (added as a devDependency; per-file `@vitest-environment`, the others stay in node).
- Storage: `storage.get/set/remove/keys` in api.ts over `core/storage.*` (`pal_core::storage`, `app/src-tauri/src/storage.rs`): one JSON object per extension in `<data dir>/pal/storage/<extension>.json` (top-level data dir, shared across profiles like the clipboard db), atomic writes, 256 KB cap (a `set` over it rejects and rolls back), keys 1..128 bytes, extension name validated as a file name, a broken file set aside as `.bak`. ## Findings

- **PATH from the Dock (2026-09-16 21:00).** Cagdas: "I already did gh auth login, but github palettes doesn't work". The host ran with launchd's `PATH=/usr/bin:/bin:/usr/sbin:/sbin` (`ps eww` on `pal-bun`), so `Bun.which("gh")` was null and every CLI-backed extension (gh, op, docker, timer, make, nmcli, sketchybar) failed when pal started from the LaunchAgent and worked from a terminal. `pal_core::env::adopt()` at the top of `run()` reads the login shell's PATH (`$SHELL -l -i -c` with a marker, 120 ms on hornet, 2 s cap, skipped when the inherited PATH already reaches past the system dirs) and merges it with the usual tool dirs; the process env carries it to the host and every `Command`.

- **Empty list with a live count (2026-09-16 20:40).** Cagdas saw the panel with hits counted in the footer ("97 of 30526", the primary action named) and no rows drawn, now and then, self-healing later. Diagnosis (guess, the state was gone): the virtualiser reads the scroll rect once at mount and then only through ResizeObserver, and WebKit holds those callbacks while the panel sits hidden at alpha 0, so a list whose rows changed while hidden could keep a zero or stale rect and draw nothing. If it shows up again with this build, the guess was wrong: capture `document.visibilityState`, the `.pal-list` client height and `virt.getVirtualItems().length` from the console.

## calc rebuilt (2026-09-16)

- `calc` was mathjs over the query and could not do `12 usd to try`. Rebuilt around three parsers tried in order (`extensions/calc/{dates,currency,math}.ts`, `index.ts` the orchestration, `format.ts` the numbers, `row.ts` the shape they answer): dates and time zones first (their keywords are unambiguous), currency second (a currency token on the right or the left), mathjs last with a rewrite pass for the idioms it lacks (`sqrt 2`, `15% of 240`, `240 + 15%` = 276, `72 f to c`, `12 gb to mb`, `100 kph to mph`, `5 ft 3 in`, `3 x 4`, `2 power 10`, `10 mod 3`). mathjs stays for arithmetic and units: its unit table is good, only the spellings were missing (`kb` there is a kilobit, so the byte aliases map to `kB`/`MB`/`GB`; `f`/`c`/`k` are degrees only across a `to`).
- Rates: the ECB reference set through frankfurter (`https://api.frankfurter.dev/v1/latest`; `api.frankfurter.app` now 301s there). Free, no key, 30 currencies, TRY included, no crypto (so `1 btc` lists nothing rather than fetching a second source; no `rate_source` setting until one exists). Fetched lazily on the first currency query, never at load; kept in `storage` under `rates` (`{ base, date, rates, fetched }`, ~1 KB, the one exception to "storage is not a cache") and refreshed after 24 h in the background: `ensureRates` awaits only the one storage read, the fetch is a module-level promise nobody awaits, so the first query without a cache answers an inert `Fetching exchange rates…` row and the next keystroke has the numbers. A stale or offline set answers dated (`rates 2026-09-15` accessory). A failed fetch backs off a minute. `PAL_CALC_OFFLINE=1` (tests, or a machine that should never call out) and `PAL_CALC_RATES_URL` (the test's Bun server) are the two env knobs.
- Rows: the result is the title (Enter copies it as shown), the query as understood the subtitle (`12 USD to TRY`), accessories the rate and date / the unit; a second row when there is another form: the other bases for a number typed as one or a bare integer (not for every integer result, `2+2` stays one row), a fraction, the reverse conversion, the ISO date, the unix time. Row ids are fixed (`result`, `base`, `fraction`, `reverse`, `iso`, `unix`) and `pick` reads the last listing from a map: an input palette relists per keystroke and the ids only need to be stable across those. Actions: Copy result, Paste result (`paste: { text }`), Copy without formatting (`cmd+shift+c`, `583.68` / `1000000`), Copy expression = result (`cmd+shift+e`).
- Silence while typing: every parser returns nothing for a query that does not parse, so no error rows; two exceptions on purpose: a target still being typed (`12 usd to tr`) keeps the source's row (a prefix of a known currency word), and a date-shaped query that is no date (`2026-02-30`) lists nothing instead of falling through to `2026-2-30 = 1994`.
- Formatting through `Intl`: `precision` (default 10, was 14) is significant digits for the fraction only, integers are never rounded (`maximumSignificantDigits` would print `2^40` as `1,099,510,000,000`); units and rates cap at 6 (`22.2222 °C`, not `22.222222222222`). `locale` (default `en`) drives grouping, the decimal separator and dates, and is applied to the input too (`1,5 + 2` under `tr`). `home_currency` empty means the time zone's currency (`Europe/Istanbul` is TRY; the Intl locale is `en-US` under a `LANG=en_US` shell even on an `en_TR` Mac, so the zone is the better signal), then the locale region, then USD.
- Zones: an alias table (abbreviations, ~120 cities and countries) over IANA ids, `utc+3` as `Etc/GMT-3` (whole hours only: no `Etc` zone has minutes), wall-clock to instant by two `Intl.formatToParts` offsets. `ist` is Istanbul (the airport code, and where the machine is), India by name; `cet` follows Berlin's DST. Without a source zone the local one; the time is today's in the source zone; `next day` accessory when the date differs.
- Tests: `host/test/extensions/calc.test.ts`, 23 tests, 168 expects, ~0.8 s: every doc example through the harness with canned rates (seeded through the harness's `stored` map before the host starts, `PAL_CALC_OFFLINE=1`), `process.env.TZ = "UTC"` so the spawned host agrees with bun test's own UTC, and two more hosts against a `Bun.serve` for the no-cache (fetching row, stored set) and stale-cache (dated answer, background refresh) paths.

Localised app names are not read (binary `InfoPlist.strings`, a spawn per app). A pre-existing `!seen.add(...)` (always false) let same-named apps repeat across roots; fixed to `has` + `add`.
- **bookmarks**: Safari's plist is read as XML through `plutil -convert xml1` and a 50-line plist reader (`sources.ts`), not `-convert json`: JSON conversion refuses `<date>`/`<data>` values and the Reading List has dates. No npm dependency (a `bplist-parser` would have meant a lockfile per extension for one file). Firefox is `bun:sqlite` over a copy of `places.sqlite`, deleted after. `PAL_BOOKMARKS_HOME` points the profile roots at a temp home for the tests, like `PAL_FILES_BACKEND`. Duplicate urls are folded (first source wins) instead of the old NUL-ordinal ids.
- **emoji**: `live` + `ttl: 30` rather than indexed: a "Recently used" section needs the extension's own order, and an indexed palette re-lists only on start/`⌘R`/settings, so a just-used emoji would have hoisted its whole category above the recents until the next start (sections are contiguous in order of first appearance). The cost is one 1906-row listing per show at most every 30 s and no frecency boost on emoji at the root. `data.json` annotated from unicode-emoji-json (`group`, `skin_tone_support`) joined on the glyph; the names and keywords stayed emojilib's.
- **clipboard**: Links and Colors are text entries narrowed on this side (the core knows three kinds); "Delete all unpinned" deletes one by one over pages because the core's only bulk operation is `clear`. A colour's icon is the hex string, which the UI already draws as a tinted dot.
- **files**: recents come from `mdfind -attr kMDItemLastUsedDate` (sortable, unlike plain `mdfind`) or `recently-used.xbel`; `PAL_RECENT_XBEL` lets the tests feed the xbel path on macOS too. The empty query of the Files palette shows them in place of the hints (Raycast's empty state); `recent` is a second palette in the same extension sharing rows, actions and detail.
- **processes**: `:port` is a query mode inside the palette rather than a filter, so a port can be typed; `ss` first, else `lsof -F pcn` (field output, since the table form truncates commands). "Open in Activity Monitor" types the pid through System Events (there is no URL scheme); best effort.
- **ssh**: the section is the file the host came from; `ping -c 1` with `-W` in ms on macOS and seconds on Linux.
- **quicklinks/snippets**: import/export is a form with a path field; `{selection}` maps to the clipboard, `{cursor}` documented as unsupported (pal pastes whole).
- Tag colours are token names only (`amber` replaced processes' `orange`).
- Docs for this pass are an appended section of `docs/palettes.md` (the earlier per-palette sections were left as they were, by the brief); the tests are `host/test/extensions/*.test.ts`, every new pure module (`apps/desktop.ts`, `bookmarks/sources.ts`, `emoji/skin.ts`, `files/recent.ts`, `processes/ports.ts`) tested without a host.

## Where a palette is described (2026-09-16)

- One rule, `docs/extensions.md` "Where a palette is described": `pal.json` holds the static, author-facing facts (`title`, `description`, `kind`, `ttl`, `keys`, `rank`, `settings`, the extension's `icon`), the code the behaviour (`list`/`pick`/`detail`/`view`, `filters`, `placeholder`, `showDetail`, `columns`, `live`, `input`). `kind` is stated by the manifest and implied by the code and must agree: `view` for a `view()` palette, `grid` for `view: "grid"`, `input` for `input: true`, `live` for `live: true` without `input`, else `list` (`kindOf` in `sdk/src/manifest.ts`, first match wins). `title` and `ttl` may sit on both sides; the manifest's is served and a differing code value is a warning (before this the code's `ttl` won and the manifest's title was never served).
- `checkPalettes(manifest, ext)` in `sdk/src/manifest.ts` (exported from `@zcag/pal`) is what the host runs on every load; it answers `{ metas, warnings }` and replaced `metas()` in `host.ts`. A code palette the manifest lacks is served from the code with a warning; a manifest palette the code lacks is not served (its meta is not sent) with a warning; a manifest with no `palettes` key is dynamic (`scripts`) and gets no cross-check. Every warning is a `[<ext>] manifest: palettes.<key>: ...` stderr line.
- **Wire addition, for the app side:** `extension/loaded` and each entry of `hello.extensions` now carry `warnings: string[]` next to `palettes` (empty when the manifest and the code agree). Additive: the Rust side already keeps `error?` per extension (`settings::register`, `Ext`); `warnings` is the same shape's non-fatal sibling, meant for the Settings window's extension row. Nothing reads it yet.
- `ManifestPalette` in `protocol.ts` now types `kind` (`PaletteKind`), `keys` (`ManifestKey[]`, `{ keys, title }`) and `rank` (number), which the bundled manifests already carried untyped; `app/src/ui/SettingsTypes.ts` mirrors `Manifest` by hand and does not have them yet.
- `defineExtension(manifest, ext)` is a second overload: `ExtensionFor<M>` maps the manifest's palette keys to the shape each `kind` demands, so a missing or extra key is a type error at the export (an inline `as const` manifest also pins the kind; a JSON import widens it to `string`, keys only). The bundled extensions still use `satisfies Extension`; nothing was rewritten to the new form.
- The sweep over the bundled extensions (`host/test/manifest.test.ts`, "the bundled extensions") found no drift today: every `kind` the content pass guessed matches the code, no title or ttl conflicts. Nine palettes carry a `ttl` in the code that the manifest does not repeat (docker x3 at 10, emoji 30, files/recent 60, home-assistant services/areas 3600, network 60, onepassword/items 300, services 10): served as before, no warning (a code value with no manifest counterpart), and the natural follow-up is to move each into its manifest and drop it from the code.

## 2048 and Wordle (2026-09-16)

Two more view palettes on the blackjack pattern (`extensions/{2048,wordle}/`: pure `game.ts`, `render.ts` for the tree, SVG tiles the extension draws, the state whole in storage after every pick; docs appended to `docs/palettes.md`, store fields and screenshots in `pal.json`, fixtures generated by `extensions/<game>/fixture.ts` into `app/src/gallery/shots/`). What was decided, and what the tree could not do:

- **Tiles are `image` nodes keyed by cell and content, with `exit: "none"`** (superseded the same day by the `tile` node and `move`, next section). A 2048 tile that slid is a new key in its destination cell and enters there; the old key leaves at once, since a fading exit would leave five children in a four-cell row for a frame. Merged tiles `flip`, slid ones `fade`, the spawned one fades with `delay: 2` so it lands after the rest. Wordle's submitted row keys each tile by row, column, letter and mark and flips with `delay: column`, which gives the staggered reveal; a typed letter fades in, a deleted one goes at once. Keying by tile id alone was rejected: a tile moving within its row would keep its DOM and jump without any transition, while one changing rows would animate, so moves would look different by direction.
- **Six rows in Wordle, side by side with the keyboard.** The brief said five rows; the original has six and a five-guess Wordle plays as a different game (the share text's `x/6` is what people recognise). Six rows of 48 px stack to 308 px, which with a keyboard under them does not fit the 358 px body, so the keyboard, the stats and the message sit to the right of the grid instead. If five was meant, `ROWS` in `game.ts` is the one constant.
- **Letters as bare-key actions.** The grammar (`app/src/ui/keys.ts` `resolve`) routes any unmodified printable key to `{ type: "key" }`, which a view with `keys: "actions"` matches against `Action.shortcut`, so a-z work as they are (by `e.code`, so a shifted or caps-locked letter is the same key, and non-QWERTY layouts go by physical key). `n` and `c` are letters mid-game, so New game rides on `cmd+n` there and on a bare `n` once the game is over; copy is `c` (and Enter, as the first action) once the game is over. The 26 letter actions are listed in ⌘K (last, titled `Type A`), since there is no way to hide an action from the panel.
- **Word lists** are built by `extensions/wordle/build.ts` from public domain sources and committed: answers from 12dicts' `3esl` + `6of12` (Alan Beale, released to the public domain) with plurals dropped by a stem check and a short block list, 2551 words; allowed from every public domain 12dicts list plus ENABLE, 8878 words; 69 KB together, inlined by `bun build` through the `*.txt` text loader. The daily is `ANSWERS[(day * 1103) mod n]`, a permutation since 1103 and 2551 are coprime (tested), so the file's order is load-bearing and the build script says so. The original's lists were not used: the NYT's curation is not public domain, and the numbers would not have matched the original's puzzle of the day anyway.
- **Undo is one move** (a `prev` snapshot on the state), allowed after game over as a rescue, and taking a win back restores `won` from the snapshot. Enter mid-game is New game with a confirm, so the footer has something sensible and a stray Enter costs nothing; at 2048 Enter is Keep going, at game over New game without the question.
- Tests: `host/test/extensions/2048.test.ts` (21: line and board slides with the no-double-merge rule, spawn odds at the boundaries and over 5000 draws, undo, the won and over phases, the tree's keys and transitions, the wire with the undo setting) and `wordle.test.ts` (21: marks with duplicates, hard mode, the lists and the daily permutation, the day index, typing and submitting, stats and the streak, sync on a new day, share text, the tree, the wire with `daily` and `hard_mode`). Screenshots through `app/scripts/shots.mjs` from the fixtures.

## Decided: what the view tree lacked for the games, and what landed (2026-09-16)

The eight gaps the games worked around were each closed in the tree's API, and the three renders rewritten on it; none of the workarounds remain. In order:

- **`backspace` and `delete` reach a view.** `resolve` in `app/src/ui/keys.ts` returns `{ type: "key", key: "backspace" | "delete" }` for the unmodified keys, so `shortcut: "backspace"` binds like `space`; `Kbd` already drew ⌫. Held in a field the key keeps its native repeat (the query clears), held on a view it fires once, the same as letters (`useKeys`, the repeat branch; before this a held letter in the search input typed once, a quirk fixed in passing). Wordle's Delete is on `backspace` alone; the `delete-alt` on `left` is gone.
- **`Action.shortcut` is a string or a list.** `["up", "k"]`: `shortcutsOf` / `hasShortcut` (keys.ts, exported from `@zcag/pal` too) match any; the panel draws the first as the key and the rest faintly before it (`.pal-action__alt`, 45%); `checkView` refuses an empty list or a non-string in it. 2048's four moves are four actions with two keys each, not eight; `game.ts` lost its `h`/`j`/`k`/`l` pseudo-actions.
- **`Action.hidden: true` routes and is never listed.** Not in ⌘K (`ActionPanel` filters), not in the footer, and not one of the Enter / ⌘Enter pair, which are the first two *listed* actions (`listed` in Launcher.tsx). `checkView` refuses a hidden action without a shortcut, since nothing could reach it. Wordle's 26 letters are hidden; ⌘K lists Submit and Delete (and New game when it is on offer). Chosen over a `View.keys` map because the action shape already carries the key and the confirm; a second table would have duplicated it.
- **Transitions: three more slides, `pop`, and `move`.** `enter` gained `slide-down`, `slide-left`, `slide-right` (the node arrives from that side, `--pal-motion-slide`, 6 px, which `slide-up` now reads too) and `pop` (a scale from 0.8 with a 6% overshoot, `--pal-motion-pop`); each has a matching exit. `move: true` is a FLIP in `View.tsx` (`useMove`): the `View` keeps a per-tree registry of moving elements; when a new tree arrives it measures every registered element's box in render, before the commit (transform included, so a slide interrupted mid-flight continues from where it is on screen); after the commit each mover's layout effect measures its new box and plays a `translate` from the old one over `--pal-motion-move` with the Web Animations API. It works across parents: a node that unmounts in one cell and mounts in another is one key to the registry, the stack it left draws no exit for it (`Children` consults the tree's moving keys), and the re-mounted node has its `enter` switched off so it does not pop while sliding. A move key must be unique in the whole tree (`checkView`). Measuring and playing happen once per tree, not per render: the first cut ran the effect on every commit and the `busy` flag flipping cancelled the slide it had just started, which is why a probe showed `animate` called and no motion. `reduced()` (presence.tsx, now exported) skips the play; the tokens are zero under reduced motion anyway.
- **A `tile` node.** `{ type: "tile", width, height, text?, sub?, color?, fill? }`: a rounded box drawn with the tokens. `color` is the tag palette plus `neutral` (default) and `accent`; `fill` is `solid` (the colour as background, the panel background as ink, which reads on both themes since the tag colours are dark on light and light on dark), `soft` (the tint, the colour as ink; default) or `outline` (a 1.5 px inset hairline). Solid neutral is paper: the elevated surface with a hairline and the bevel, what a 2 tile and a typed letter want. The type is set inline (`tileType`): the size scales with the box and shrinks with the text's length (a 64 px tile shows "2" at 28 px and "2048" at 21), weight 800 from 20 px, 700 from 14, tabular figures throughout. Under 44 px the box takes the control radius, so a keyboard key is not a pebble. The SVG tile modules of both games (`tiles.ts`) are deleted; 2048's ramp climbs in weight only (`lookOf` in render.ts): paper for 2, the neutral tint for 4, then solid tiles walking the hues warm to cool (amber, red, pink, violet, blue, teal, green), the grey chip at 1024, the accent at 2048 and past it. A first cut alternated soft and solid per hue and read as a sawtooth (512 in the pink tint looked weaker than 256 in solid violet), so no two fills alternate; the palette has no orange, so 16 is red rather than a second amber next to 8.
- **`stack.surface` and `radius`.** `sunken` is `--pal-bg-sunken`, `elevated` is `--pal-bg-elevated` with a hairline and the bevel; `radius` is the tile radius. 2048's and Wordle's boards sit in a sunken well with `padding: 2`, blackjack's table in one with `padding: 3` (the status row stays outside), Wordle's stats on an elevated card.
- **`text.width` / `minWidth` / `align`, `progress.color`.** A text with a width is a column: `flex: none`, clipped with an ellipsis instead of wrapping, `align` inside it. Wordle's distribution is a label of 8 px, a 96 px bar (`value` is the share of the fullest row, `color: "grey"` except the winning row, which keeps the accent) and a count of 20 px right-aligned, in place of the `progress` of computed width.
- **A queue of keys while a pick is in flight.** `viewCommand` in Launcher.tsx is the one entry for a view level's keys (Enter, ⌘Enter, a combo, a bare key); while `busy` it pushes the command onto a FIFO of four and an effect drains one per settled tree, resolving the key against the *new* actions, so a "hit" typed a beat early lands on the hand it was meant for or on nothing. A queued key no action carries is dropped and the next tried. The queue is emptied when the level changes (`levelKey`: depth and palette). A form level still drops a second Enter.

The games on the new API: 2048's cells are stacks (`cell0..15`) each holding one tile, an outline for an empty cell or the tile keyed `t<id>` with `move`; a slid tile glides across the board (rows too), a merged one pops in its cell one step after the slide starts, the spawned one two steps. Wordle's board tiles and keyboard are `tile` nodes (outline empty, paper typed with `pop`, green / amber / grey marks with the staggered `flip`), the letters hidden actions, Backspace routed. Blackjack's player cards are keyed by deal and card (`p-<card>[#n]-<deal>`, a repeated card numbered) with `move`, so a split's second card glides to its new hand; the dealer's keep their slot keys. A `fixture.ts` for blackjack now generates its shots fixture like the other two (it reproduces the states the hand-made JSON had).

Tests: `app/src/ui/__tests__/view.test.tsx` (tile, surfaces, text width, progress colour, the entrances), `move.test.tsx` (the FLIP across cells with a stubbed layout, a new key entering instead, reduced motion), `keys.test.tsx` (Backspace and Delete, `shortcutsOf`, the held-key rule), `app/src/__tests__/view-level.test.tsx` (Backspace and either shortcut routing to picks, hidden out of the panel and footer with the alternative drawn faintly, the queue of four run against the replies, dropped on leaving); `host/test/view.test.ts` (shortcut lists, hidden without a key, every entrance and exit, `move` without a key or with a key used twice, tile / text / progress / stack fields). The game tests were updated to the new trees. The tokens' brief (`app/design/build.py`) was rebuilt; its meta lacked two settings tokens too, added.

Not done, deliberately: the merged tile's two sources vanish at once and the merged tile pops in place, rather than the sources sliding under it as in the original; that would need the game to report which tiles merged into which, and the pop reads well enough. The `--pal-motion-*` names are the first tokens outside the `--pal-dur-*` / `--pal-ease*` pair; they are what the view's motion reads, the shell's own motion keeps the durations.

## Colours: the picker, the sampler, and what the view tree gained for it (2026-09-16)

`extensions/colors` went from two palettes (a 700-swatch grid and a converter) to the extension people would install pal for; Raycast's Color Picker and Digital Color Meter were the behaviour references, the look is the tokens'. What landed, and what it took from the shell:

- **Four palettes over one maths.** `picker` (a view level: the swatch on a sunken well over a hue strip and a saturation/lightness plane, every notation as copyable rows, the nearest Tailwind and Material tokens, contrast on white / black / the previous colour with the WCAG badge, nine tints, nine shades and five harmonies as tiles), `colors` (995 swatches: CSS, Tailwind 3.4, Material 3 tonal palettes generated from the baseline seed with Google's material-color-utilities at build time, Material 2014, Apple light and dark, Catppuccin, Rosé Pine, Nord, Solarized, pal's tokens; a filter per set; the detail says where the token is used), `history` (live, so the root's rows follow every pick and copy: each colour with when and where from, `Pick Colour from Screen` as its first row and so at the root), `convert` (Enter now opens the picker). State in `state.ts` (pure), the tree in `render.ts`, the rows in `rows.ts`, the sets in `sets.ts`; `color.ts` gained CIE Lab against D50 with the CSS Color 4 matrices, display-p3 through XYZ, OKLab strings, gamut-aware OKLCH steps (chroma reduced by a binary search rather than channels clipped), tints, shades, harmonies and the formats. The maths is checked against the spec's reference points (red is `lab(54.29 80.8 69.89)`, `lab(29.2345% 39.3825 20.0664)` is `#7d2329`).
- **The keys.** `←`/`→` hue, `↑`/`↓` lightness, `-`/`+` saturation or chroma, `⇧` big steps, `m` HSL/OKLCH, `⇥` walks the tile rows (arrows along, Enter takes the tile), a digit or `#` opens the text field, `c`/`⌘C` copy, `p` picks from the screen, `h`/`n` the other palettes, `u` undo, `r` random. Saturation has no big step: `⇧-` is `_` and `⇧=` is already `+`, and a third key pair was not worth the table.
- **`core/color.sample`** (`app/src-tauri/src/color.rs`, `color.sample()` in the SDK): hides the panel on the main thread, then `NSColorSampler` (`showSamplerWithSelectionHandler:`, run and answered on the main thread, the colour converted with `colorUsingColorSpace:` sRGB; no permission) or, on Linux, the `Screenshot.PickColor` portal over zbus's blocking API with the `Response` signal subscribed on the request path before the call (`request_path` mangles the unique name; the signal stream has no timeout of its own, so a thread feeds a channel). The bridge thread waits up to 120 s; the SDK call carries the same timeout (`runtime.call` grew an `opts.timeout`, the host bridge's 5 s stays the default). Cancel is `null`. Compiles clean on marko (`cargo check -p pal` over a copy); the portal path itself is unverified on Linux.
- **Why `effects.run` exists.** A pick is bounded by the host's 10 s `REQUEST_TIMEOUT`, and a person aiming a loupe takes longer, so the picker's `p` returns `{ hide: true }` at once and samples in the background; the colour then has to reach the panel from outside a pick. `core/effects.run { effect }` runs an `Effect` envelope as `effects::apply` would (copy with the HUD, open, paste, focus, layout, hud) plus `push`, which is `show_in(app, Some("ext/palette"))` (the page opens the palette afresh, so the picker's `view()` draws the picked colour); the webview-side effects (`toast`, `keep`, `view`, `form`, `show`) are refused with the reason. The root row does `{ copy, hud: "Copied #…" }` the same way. The extension's `view()` awaits an in-flight sample before reading storage, so a panel brought back early still draws the new colour; the sample task itself reads storage without that wait (the first cut deadlocked on its own promise, caught by the harness test).
- **The view tree gained three things.** `tile.color` takes a hex colour (`HexColor`, `HEX_COLOR` in view.ts): the box is that colour whatever the fill, the ink black or white by WCAG luminance (`inkOn`, threshold 0.179 where the two ratios meet), a checker under a translucent one, a hairline in it for `outline`. A **`gradient` node** (a hex `fill` under `layers` of CSS linear gradients whose hex stops may carry alpha, in paint order so a later layer composites over an earlier one, a `marker` ring at fractions of the box drawn white over a dark halo so it reads on any colour) draws the hue strip (seven pure hues) and the classic saturation/value plane exactly (`fill` the pure hue, `#ffffff` to `#ffffff00` rightwards, `#000000` to `#00000000` upwards) with no image at all; the first cut built the plane from discrete opaque stops and read as painted patches. In HSL mode the marker is the colour's HSV coordinates (the arrows still move HSL); in OKLCH mode the same plane stands in with the hue's most chromatic sRGB colour as the fill and the marker at the chroma as a share of the gamut's width at that lightness, smooth rather than exact. ## Decided: links (2026-09-16)

Spec `docs/design/links.md`, user doc `docs/links.md`, authors' section in `docs/extensions.md`, `docs/cli.md` updated, `STORE-FIELDS.md` in pal-site tells the site how to render `links`. Built while the surface is small, so every later feature lands with a link.

- **One grammar**: `pal://<route>[/<part>...][?k=v]`, parts percent-decoded one by one (an encoded slash stays inside an id), `+` a space, a repeated key an array, `args` percent-encoded JSON. The first part is a reserved route or an extension's name (`pal://timer/start?duration=25m`); the table order settles a clash (an extension named `open` cannot be linked, documented). `deeplink.rs` is table-driven: `ROUTES: &[Spec { pattern, doc, build }]` with `{name}` parts and a `{spec...}` rest, matched top to bottom, one example per row in the tests (`every_route_in_the_table_parses_to_its_route` fails when a row lacks one); `pal link --list` prints the table.
- **Every link has a CLI twin**: `pal link URL` plus `open run form copy paste hud toast confetti command call` (`Cmd::link()` spells the url, the tests round-trip each through the parser). A twin is handed over as its own argv, the instance spells the link again and runs it **trusted**: no confirm card, the shell is the user's hand. A link the grammar refuses never leaves the CLI process (reason on stderr, exit 2); a handed-over link exits 0 and the outcome is the HUD's (no reply channel over single-instance; documented rather than faked).
- **What is addressable**: the app (`show hide toggle settings[/page] reload quit`, pal's own rows as `commands/<id>` with `run/pal/commands/<id>` kept as an alias), a palette (`open/<ext>/<palette>?q=&filter=`), an item (`run/.../<id>?action=&args=`), a form (`form/.../<id>?field=value`: the same pick, its `form` answer prefilled by `prefill` and shown in the panel, nothing submitted), effects from outside (`copy paste open?url= hud toast confetti`), the store (`install update remove`), a bar item (`bar/<ext>/<id>[?action=]`), extension routes. `pal://extensions` stays as the old spelling; nothing was renamed.
- **A link's answer goes where it belongs** (`deliver`): a `toast` is the HUD's line with the panel down; `push`/`show`/`view`/`form` show the panel and hand the page `pal://deeplink { effect, item }`, which `Launcher.apply` runs through the same `applyEffect` a pick's answer takes (extracted from `pickItem`). `pal://toast` while the panel is up is a toast in it, else the HUD. `pal://confetti` is `hud::celebrate`: the HUD payload grows `celebrate`, the `Hud` component bursts 24 CSS particles (`.pal-hud__confetti`, nth-child over the tag palette, one keyframe, reduced motion zeroes the hold so they never fly). Cheap enough to keep.
- **What asks**: `general.deeplink_confirm` is `pal_core::config::Confirm`, `true`/`false` or a list of extension names trusted without the card (`Confirm::asks(extension)`; the extension is the path's, a bar key's first part). `run`, `form`, a bar action, an extension route obey it; `paste` and `open?url=` (no extension, a page must not type into the front app or launch a file) follow the boolean; `install update remove` always ask; a manifest route with `confirm: true` always asks (system's `run`); the CLI never. Schema regenerated (`cargo run -p pal-core --example schema`).
- **Extension routes**: `pal.json` `links.<route>: { description, confirm?, params: { <name>: { description, required?, type } } }` (`type` one of `string number boolean json string[]`), code `Extension.link(route, params)` answering an Effect. Host method `link`: the manifest gates the route (undeclared = `no route x/y`), `checkLinkParams` (sdk/manifest.ts) refuses a missing required param naming it and coerces by type, `checkLinkEffect` refuses `keep show view form` (the `effects.run` set), then `checkEffect`. `checkLinks(manifest, ext)` runs on every load next to `checkPalettes` and its warnings ride the same `warnings` (a block without a handler, a handler without a block, a bad route name, a bad type). The core reads the manifest's `links.<route>` from `settings::manifest_of` for the card's text and `confirm`. Routes shipped: `quicklinks/open?name=&query=`, `snippets/paste?name=&copy=`, `window-management/layout?name=`, `system/run?id=` (`confirm: true`), `timer/start?duration=&name=&ring=`, `clipboard/copy?index=`. `calendar/join-next` and `colors/pick` are specified in `docs/design/links.md` and left for those extensions' agents (their directories were another agent's this round).
- **Copy deep link** (⌘⇧C, section Link): a shell action on every row (`run/...`, a palette row's `open/...`, a pal row's `commands/<id>`, a drill-in row with `?args=`), inside a palette or view with nothing under the cursor (`open/...?q=`), on a form (`form/...?action=`, the form level now remembers the action that opened it), on a bar menu row (`bar/<key>?action=`). `app/src/links.ts` `linkFor(level, item, query)` is pure and tested; the page writes `pal://` and `link_copy` (a Tauri command) hides the panel, swaps in the bundle's scheme (`plugins.deep-link.desktop.schemes[0]`) and copies with the HUD saying `Copied pal://...`. Not on the settings pages: `app/src/ui/Settings*.tsx` were another agent's this round; the pages are addressable (`pal://settings/<page>`) and the action is one `onLink` call away.

## media: the MediaRemote adapter replaces nowplaying-cli on macOS (2026-09-16)

- **The fact.** Since macOS 15.4 `mediaremoted` answers only clients with the `com.apple.mediaremote.*` entitlement. On hornet (macOS 26.4, build 25E246) with a YouTube tab playing in Chrome, `nowplaying-cli get title artist playbackRate` printed `null null null`; the `media` palette therefore saw nothing beyond Spotify and Music and told Cagdas to `brew install nowplaying-cli`, which he had. `nowplaying-cli`'s own README says the same for 15.4+.
- **The fix.** pal bundles [mediaremote-adapter](https://github.com/ungive/mediaremote-adapter) (BSD-3-Clause, Jonas van den Berg; `NOTICES.md`): a Perl script and a small Objective-C framework; `/usr/bin/perl` is an Apple-signed, entitled binary with no library validation, so `DynaLoader::dl_load_file` on the framework gives the script the MediaRemote API. `perl mediaremote-adapter.pl <Framework> get --now --no-artwork --allow-missing-title` prints one JSON object (or `null`), `send <MRCommand id>` controls (0 play, 1 pause, 2 toggle, 4 next, 5 previous). `app/scripts/fetch-mediaremote.sh` clones the pinned commit (`73f14ab`), builds with cmake (universal, ad-hoc signed by its own post-build step, ~8 s on hornet, needs `brew install cmake`; the CI macOS image has cmake) into `app/src-tauri/mediaremote/` (gitignored); `build.rs` runs it when the script is missing, `tauri.macos.conf.json` ships the directory as `Contents/Resources/mediaremote` (macOS only: the Linux bundle never sees it). `pal_core::media::configure(dir)` (called from `app/src-tauri/src/media.rs::install` with the bundle's Resources, else the repo dir) is the resolver; the source order is adapter, then `nowplaying-cli` on PATH, then only the osascript apps.
- **What Chrome/YouTube returns on hornet.** `{"bundleIdentifier":"com.google.Chrome","playing":true,"playbackRate":1,"title":"","artist":"","album":"","duration":3963.08,"elapsedTime":2411.41,"elapsedTimeNow":2532.90,"timestamp":"2026-09-16T17:49:16Z","processIdentifier":79336,"contentItemIdentifier":"…"}`: the app, the state and the position, every text key empty. Without `--allow-missing-title` the adapter prints `null` for it ("media without a title is invalid" by its default), so the flag is load-bearing. `elapsedTime` is the position at `timestamp`, which was minutes stale on one read (a 17:34:50Z timestamp on a read made around 17:40, position 1547 s of a 3963 s video); `--now` adds `elapsedTimeNow`, which the row uses. The row is then "Google Chrome" (the running app's `localizedName`, its bundle path for the icon) with "42:12 / 1:06:03" as the subtitle and the `playing` tag; the bar strip says "Google Chrome". Twenty minutes later the same tab read `"title":"Taylor Tomlinson (Full Episode) | Conan O'Brien Needs A Friend","artist":"Team Coco"` (a new `contentItemIdentifier`, timestamp 17:55:49Z): YouTube's media session does reach Chrome's Now Playing, late; the empty keys are the gap, and the title-less row covers it instead of "Nothing playing" beside a `playing` tag. Both captures are fixtures.
- **In the bundle.** tauri's resource copy (`bundle.resources`) does not keep symlinks: the framework arrives with `MediaRemoteAdapter` as a real file at the top and `Versions/A/` beside it, no `Versions/Current` or `Resources` links. The script dlopens `<framework>/MediaRemoteAdapter`, so that is enough; the Mach-O's own ad-hoc signature is untouched (`codesign -dv` reads `com.vandenbe.MediaRemoteAdapter`, adhoc) and Resources is not a nested-code location, so neither the ad-hoc app signing nor `make app`'s `pal-dev` identity (tested: `codesign --force --deep -s pal-dev` on a copy) re-signs or rejects it; `codesign --verify --deep --strict` passes both ways and `get` runs from `Contents/Resources/mediaremote` at 20.6-22.4 ms. `/usr/bin/perl` does no library validation, which is the whole trick; hardened runtime is off anyway.
- **Latency.** `perl` + framework load + `get`: 19-21 ms per run on hornet (10 runs, min 19.0, median 19.9, max 21.2 ms), `send` 18-20 ms; the whole `now_playing()` in a debug build, with the two `NSRunningApplication` checks, 44.6 ms. Well under the 100 ms target, so `get` runs on the existing cadence (the bar's 5 s poll while playing, the 30 s core refresh) and there is no long-lived `stream` process. Option kept for later: one `stream --no-diff --no-artwork` child in the core, answered from its last payload, which would make a track change push-driven instead of polled; nothing needs it at 20 ms. **Superseded the same day: the stream landed (Decided: media stream, below).**
- **Artwork** was off (`--no-artwork`; the stream now carries it, below): the adapter emits it as base64 `artworkData` (a few hundred KB per read) and says it arrives late and unreliably for `get`; a `data:` url on the row at every 5 s poll is not cheap. Spotify's row has its https artwork url anyway; Music's has none either way.
- **Dedupe** is now by bundle id: when the adapter names `com.spotify.client` or `com.apple.Music` and that app's osascript row exists, the system row is dropped (the app row has the urls); the nowplaying-cli fallback still dedupes on title+artist since it has no bundle id.
- **Palette and bar.** A title-less player with a state is a row (app name, position or "Playing"/"Paused" as the subtitle, no Copy); the macOS install hint is gone (the adapter is always in the bundle; a build without it says so), the Linux `playerctl` hint stays. `clock()` and the Chrome fixture are tested in `host/test/extensions/media.test.ts`; `parse_mediaremote` against the captured Chrome JSON, a README-shaped paused track and `null`/`{}` in `core/src/media.rs`; `mediaremote_live` (`#[ignore]`) runs the whole chain against the box.
- **Control test.** `send 2` twice, 1.5 s apart, on Cagdas's Chrome while measuring: playback paused and resumed, `playing` was true again after.

## Decided: Hue (2026-09-16)

- **What landed** (`extensions/hue`): eight palettes (`rooms`, `lights`, `scenes` as lists; `light` and `setup` as views; `sensors`, `automations`, `entertainment`), the bar item `hue/home`, three links (`toggle`, `scene`, `off`), all over CLIP v2 on the LAN: `api.ts` (the client, discovery, press-link, the SSE reader, the certificate peek), `model.ts` (one `Home` of every bridge's resources, the event merge, the derived rooms/lights/scenes/sensors/automations/areas, slugs), `color.ts` (xy to and from sRGB with the gamut triangle clamp, the Planckian locus for a mirek's white, HSV for the plane, lux), `rows.ts`, `render.ts` (the light/room view and the setup view as trees), `png.ts` (a disc for the bar), `sample.ts` (the home the fixture and the mock share), `fixture.ts`. The v1 API is used for exactly one thing v2 lacks, pairing (`POST /api`).
- **Live means the model, not polling.** One `GET /clip/v2/resource` per bridge at load, then the bridge's event stream (`/eventstream/clip/v2`, `text/event-stream`, one `data:` line per block carrying an array of `{ type: update|add|delete, data: [partial resources] }`, parsed by hand in `parseSse`) patches the map (`Home.merge`: objects merged, arrays replaced, an `update` for an unknown id ignored, an `add` inserted). Reconnect with backoff 1 s to 60 s and a whole re-read after a gap. So a listing, a view or a bar render is drawn from memory; the rows and the bar follow the Hue app or a switch. A write is one `PUT`, applied to the model at once (`applyLocally`, with `effects.effect` written as `effects.status`, the name the bridge reports it under) and confirmed by the stream; `put` keeps one in-flight body per resource and sends the newest queued state after Hue's gap (100 ms per light, 1 s per group), so a held arrow is one command and a room toggle followed by "Turn on" is two, a second apart. Rate guidance from Hue's docs; the coalescing is tested.
- **What the view cannot do**: redraw without a key. There is no channel to push a tree into an open level (`effects.run` refuses `view`); the model is current, so the next key's tree is right, and the README and the palette doc say so. A `view/update` notification would close that gap; it belongs to the shell.
- **Ids are slugs**, unique per kind (`room:living-room`, `scene:living-room/relax`, `light:lamp-2` for a second Lamp; `slug()` folds accents and Turkish dotless i), so a deep link and an `item_hotkeys` entry read without a UUID; a rename changes the id. The bridge's UUIDs never leave the model.
- **TLS, pinned.** Every request is https with Bun's `tls: { ca, checkServerIdentity }`. `ca` is Signify's `root-bridge` CA (`cert.ts`; from the developer site's "Using HTTPS" page, which is behind a login, via github.com/callionica/hue's copy of 2021-09-23; sha256 `F0:BD:8E:65:…`; it verified the owner's bridge with `openssl s_client -CAfile`, return code 0, and the extension's `config()` read that bridge over it in 114 ms) plus the leaf pinned at pairing, which is what makes an older self-signed bridge work; `checkServerIdentity: () => undefined` since the CN is the bridge id, not the address. Measured on Bun 1.4.2: `checkServerIdentity`'s return value and throws are ignored by `fetch`, `rejectUnauthorized: false` skips the callback altogether, and `getPeerCertificate(true)` gives no issuer chain; so the CN check is done at pairing over `node:tls` and the chain check is the protection. `insecure = true` is the escape hatch and is documented as such.
- **Pairing is a view with a background task**, since a pick may not wait thirty seconds: `startPairing` polls `POST /api` every second until the window closes, the view shows the seconds left as of its render (Enter checks at once), and success stores the bridge, connects it and calls `effects.run({ push: setup })` to bring the panel back on "Paired"; a miss is a HUD line. The key lives in storage (`bridges`, with the client key and the pinned PEM); the SDK has no `settings.set`, so the paired view tells the user to copy the key (`c`) into the secret setting for the keychain, and a `bridge` + `application_key` pair in the settings wins over storage for that address. Discovery is the cloud endpoint and mDNS in parallel, then `GET /api/0/config` per candidate; `dns-sd -B`/`-L` never exit, so `runFor` stops them 400 ms after their last line (5.0 s down to 0.8 s on hornet).
- **Rooms' colour**: a mean of a blue strip and two whites is grey, so a room's tile is its lit lights' colours as stripes (an SVG data url, faded by the grouped brightness, an outline when off) and the one colour that stands for the room (the bar's dot, the room view's tile) is the most saturated of them. The bar's dot is a PNG (`png.ts`, 36 px, deflate through `node:zlib`) because the menu bar decodes PNG only; the gallery's bar page draws glyphs only, so the bar fixture shows the bulb in amber and the captions say so.
- **The real bridge, seen but untouched**: `discovery.meethue.com` answered `ecb5fafffe8c0231` at 192.168.1.25, mDNS `Hue Bridge - 8C0231` (`ecb5fa8c0231.local`), `GET /api/0/config` says BSB002, api 1.78.0, sw 1978293000; the certificate's CN is the id, issuer `root-bridge`. No press-link was done and no light was changed (Cagdas holds Hue through Home Assistant today, which has its own key); `/clip/v2` and the event stream answer 403 with an HTML page for an unknown key, which the client maps to "rejected the application key" before parsing. Everything else is verified against the mock.
