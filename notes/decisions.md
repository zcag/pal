## Decided

### Product

- Clean rewrite on the orphan branch `pali`; v1 stays on `main`, checked out at `~/proj/pal-v1`. `pali` takes over `main` when done.
- Name is `pal`; `pali` is the iteration. A standalone app people download, macOS and Linux. Raycast and Spotlight are the behaviour references; the visual identity is ours.
- Bar: high polish everywhere, no corners cut, minute UX details thought through.
- Root search: one box across everything; palettes are sections and drill-downs, not a root that lists palettes.
- Extensibility, one way: every palette including every default is an extension against the same API, no native tier. In-app code is shell (root search, action panel, settings, store, first run) plus OS capabilities as APIs (clipboard, windows, apps, files, hotkeys).
- Order of work: UI first (brief, component set, keyboard grammar), then protocol and host. Done in that order (`git log`).
- The pit board (pit.cagdas.io) holds Raycast research; its `in` lane is "relevant", never a commitment. Decisions are made here.

### Shell

- Tauri v2, the shape of Raycast 2.0. Go/no-go on hornet, dev build: hotkey to paint ~30 ms steady (706 ms first show, fixed by pre-painting), keystroke to list 14-42 ms over 14.7k rows, 14.7k rows streamed from a child in ~70 ms.
- Hotkey on hornet: Ctrl+Space (Alt+Space is taken); from `general.hotkey`, re-registered on file change (`hotkey.rs`). `general.position`: `top` (20%), `centre`, `last`.
- Settings window: second Tauri window on the same bundle (`index.html?settings`), hidden until asked, closes to hidden; opened by `pal-app settings`, the `pal:settings` root action, `cmd+,`. Escape / cmd+w hide it. Since 2026-09-16 it is built in `settings.rs` (`create`), not tauri.conf.json, so the macOS options stay behind `cfg`: a preferences-window shape after Raycast's, 720 by 520 (min 640 by 480, `tauri-plugin-window-state` remembers size and position for this window only, saved on every hide since a hidden window is where pal is killed), overlay title bar with the title hidden and the traffic lights moved to (13, 20) so they sit mid-band in the page's 52px toolbar, `transparent` plus `window-vibrancy` Sidebar behind `--pal-bg-glass` (Linux: decorated, opaque `--pal-bg`). The page: icon tabs centred on the toolbar (General, Palettes, Extensions, About), one search field on its right whose hits replace the page, forms as elevated cards at a 560px measure with a 160px right-aligned label column; two-pane pages (Palettes, Extensions) put a 220px list left. `theme.ts` also sets the window's own appearance (`setTheme`), else a pinned light theme sits on dark vibrancy and dark scrollbars. Links open through `settings_open_link` (the webview has no `target=_blank` handler; a plain `<a>` did nothing). Verified on hornet with the scratch bundle: note yabai tiles it like any other window (the window fills the space unless a rule floats it, e.g. `yabai -m rule --add app="^pal$" title="^pal Settings$" manage=off`), which is not something pal can fix from inside.
- HUD (`hud.rs`, `panel/{macos,linux}.rs`, `app/src/HudPage.tsx`): a third window `hud` (`index.html?hud`, 480 by 72, transparent, no decorations, `focusable: false`) for the one-line confirmation after the panel hides. macOS: an NSPanel like the main one but never key (`can_become_key_window: false`), status level, all Spaces, mouse ignored, no window shadow (the capsule draws `--pal-shadow-hud`); kept alive hidden the same way (alpha 0, never ordered out, occlusion detection off), so the same screen-lock caveats apply. Linux: a plain always-on-top toplevel, pre-mapped at startup; same class as the panel, so the compositor rule for the HUD keys on its title `pal HUD` (`notes/linux.md`). Placed bottom-centre of the work area of the monitor under the cursor (else the panel's), 8 px up; the capsule sits 24 px inside the window. `hud::show(app, text)` emits `pal://hud` to that window, shows it, and hides it after 120 + 900 + 240 (+ 60) ms; the page runs the brief's motion (in 120, hold 900, out 240 via `--pal-dur-hud-out`) and a new show restarts both clocks. Uses: `copy` shows "Copied" when the envelope hides (not with `paste`, `keep`, `toast`, `push`, `show`, or an own `hud`), `paste` nothing (the target app is the feedback), `toast` unchanged, and an extension's `{ hud: "text" }`. The page is the `Hud` component and nothing else: no list, no host calls. Verified on hornet with a scratch release instance (own identifier, own config, `XDG_DATA_HOME` aside): capsule painted 0.35 s after the trigger, gone by 1.75 s, and two triggers 0.6 s apart kept it up at 1.3 s.
- Menu bar icon (`tray.rs`): there is no Dock icon, so this is the way to Settings and Quit. Menu: Open pal (hotkey as accelerator hint), Settings… (⌘,), Restart extension host, Check for updates… (disabled until the updater flow is in; `updater::check` exists), Quit pal. Left click opens the menu (Raycast does). Image `app/design/tray.svg` (the app icon as one colour: the slab's outline with the caret and the empty query inside): black template `icons/tray/36x36` + `18x18` on macOS, white `22x22` for Linux panels. `general.menu_bar_icon = false` removes it live; `true` default, unset by the view.
- `general.launch_at_login` via tauri-plugin-autostart (`autostart.rs`): `~/Library/LaunchAgents/io.cagdas.pal.plist` (written, not `launchctl load`ed: next login) / `~/.config/autostart/pal.desktop`; applied on every change of the key. A debug build never registers (would point at `target/debug/pal`) and logs so.
- Quit (tray, `pal quit`): host gets EOF and 2 s (`Host::stop`, no respawn), then `app.exit(0)` runs the `RunEvent::Exit` flush of frecency and the cache saver (`quit  flushed` in the log). `pal quit` with no instance prints `not running`, starts nothing.
- Data keyed by config file: `<data dir>/pal/<profile>/{index, frecency.json}`, `<profile>` = `default` for `~/.config/pal/config.toml` else first 8 hex of sha256 of the canonical path (`ConfigFile::profile`; logged at startup as `profile`). `clipboard.db` stays one level up: history, not a view of one config. Nothing migrated.
- Index persisted (`cache.rs`): every default listing to `<data dir>/pal/index/<extension>/<palette>.json` (wire items, `listed_at`, meta, extension title; atomic, debounced 500 ms per source; >50k items not written). `index::restore_cache` restores all before the host spawns (items `stale`, registry entry, palette row, hotkeys): first query 32 items at ~400 ms cold vs the full ~15.5k at ~400 ms warm. `host/ready` prunes extensions gone from disk (`known`; failed-to-load keeps its cache). Restored order `pal/palettes`, `apps`, then by name, so a cold frecency profile still leads with palettes and apps.
- `ttl` is palette meta (seconds; palette object, manifest `palettes.<key>.ttl`, `scripts` maps v1 `ttl` else its own setting). On `extension/loaded`: no `ttl` = list now; younger than `ttl` = keep restored rows; else one sequential pass 1 s after `host/ready` (`refresh_expired`). `live` still re-lists on show (within the budget under Core). `SourceInfo.stale` = listing pending: footer "updating…" + search sweep. `index_refresh(source?)` / `pal:refresh` (cmd+r) force past `ttl`, the `list` carries `refresh: true` so an extension's own cache steps aside.
- d811024: hotkey apply deadlock, request timeout covering the write, stray rows after an extension leaves, zombie open children, bounded icon threads, poison-tolerant locks, `events`/`registry` modules.

### Core

- Matching in Rust: corpus in the core, `nucleo-matcher` single-thread, per-field scoring (name 100%, keyword 80%, subtitle 50%), top 200 to the webview, frecency hook before the top-N select. Numbers and why: `notes/matching.md`. Wired in 92dc234.
- Windows and system commands are core capabilities (`pal_core::windows`, `pal_core::system`; `core/windows.{list,close,minimize}`, `core/system.{commands,run}`), the `windows`/`system` extensions thin over them. Focus is a pick effect (`{ focus: id }`, effects.rs), like `paste`: the panel hides first so orderOut hands key focus back. `system.run` hides the panel itself.
- Accessibility in `pal_core::ax` (`trusted`/`request`, `AXUIElement` wrapper); the `accessibility_blocked` toast in effects.rs is paste's, the system prompt (`ax::request`) is shown once per run across paste and focus.
- Focus without Accessibility activates rather than refuses: `pal_core::windows::activate(id)` brings the window's app forward (app-level, no AX needed; `focus` reuses it after its AX raise) and returns the app's name; effects.rs hides the panel, activates, and once per run shows the HUD "Switched to <app>; per-window switching needs Accessibility" plus the system prompt. A toast cannot carry that message: the activation makes the panel resign key, which hides it (`panel/macos.rs`). With the permission nothing changed. The decision path is `focus_feedback` (unit-tested); Linux is unaffected (`ax::trusted()` is always true there).
- macOS window list: CoreGraphics (ids, order, bounds, on-screen) matched to AX windows by frame and title; titles from AX (CG needs Screen Recording for other apps' titles); an app answering AX with no windows falls back to CG rows; AX asked per app in parallel (10-30 ms when it naps).
- Linux backends detected, not configured: Hyprland (`hyprctl` + instance signature, newest `$XDG_RUNTIME_DIR/hypr/*` when the env var is missing), Sway (`SWAYSOCK`), X11 (`DISPLAY` + `wmctrl`). Hyprland has no minimise: parked on `special:minimized`, `focus` brings it back.
- Clipboard retention has one meaning (fcb967a): `max_age_days = 0` = no age limit; `exclude_apps` default in the manifest, so an explicit `[]` no longer drops the Keychain/Passwords protection.
- Exact name over history (`index::EXACT_BONUS = 1000`): an item whose trimmed name, or a keyword (alias), equals the trimmed query case-insensitively (no accent folding) gets +1000 after boost, before the top-N select; among exact hits score (with boost) then name length still order. Sized against the frecency maximum of 200 (`MAX_SCORE * BOOST_SCALE`) plus the fuzzy-vs-keyword-exact spread (nucleo ~16 per char, a keyword hit is 80% of a name hit: 33 apart at `chrome`); the welcome source's 1e9 is on the empty query only, where nothing is exact. Fixture corpus, frecency max on the other item: `ha` was harp 262 / ha 62, now ha 1062 / harp 262; `slack` with `snowflake_check` +200: Slack 1140 first. Cost: `ha` median 520 us, `chrome` 302 us (was 432 / 310). Trade-off, measured: `chrome` puts the nerd icon `chrome` (1166) above a hot Google Chrome (366) that used to lead at +30; `google chrome` or a keyword `chrome` on the app is the way back. No prefix bonus: nucleo scores prefix, word-start and exact alike (`ha`, `hat`, `Claude Code URL Handler` all 62), so a bonus that mattered against a boost would have to be at least the boost, which is the case frecency is designed to win (`term` with `terminal_tmux` +200 stays boosted-first); the length tie-break orders equals.
- `scripts` `ttl` setting defaults to 3600: no v1 plugin on hornet declares one, so every script ran on every start. A table's own `ttl` wins; a `live` table without one is exempt (a `ttl` now skips the show relist, and `otp` reads the Messages db for the current code); one resolved value feeds both the core's across-restarts keep and the extension's in-process cache. Bundled TypeScript extensions keep "no `ttl` = list on load": they are cheap (`docs/extensions.md`).
- Window layouts (`pal_core::windows::layout`, `windows::apply`; `core/windows.{frame,set_frame,displays,focused,layout}`; the `layout` pick effect in effects.rs; `extensions/window-management`): Raycast's set as one static row per layout. The arithmetic is pure and unit-tested on a 1440x900 visible frame and a two-display case; the OS part is `frame`/`set_frame` (macOS `AXPosition`/`AXSize`, the displays from `NSScreen` `frame`/`visibleFrame` flipped into the CG space, called off the main thread the way tao does; Hyprland `movewindowpixel exact`/`resizewindowpixel exact` after `setfloating` on a tiled window, `monitors -j` minus `reserved`; Sway and X11 written to the tools' documented shapes, fixture-tested only) and `focused` (frontmost app's `AXFocusedWindow`, `hyprctl activewindow`). The effect hides the panel first so the focused window is the one behind it, then the HUD names the layout or the refusal. `restore` is per window, in memory, and goes back to the frame before a *run* of pal layouts (a hand move in between starts a new run; `original_of`, unit-tested). Verified with the example binary on hornet (a hidden TextEdit document: seven layouts, restore, gap 10, frames read back exactly) and on marko (a spawned kitty over Hyprland, the focused path included). `palettes.<id>.item_hotkeys = { left_half = "ctrl+alt+left" }` registers per-item global hotkeys that run `index::run_pick` with the panel down (hotkey.rs `Target::Item`; root beats palette beats item in a clash); config-only, not in the Settings table.
- Live relist budget (`index::relist_due`, `LIVE_RELIST_GAP = 2 s`): on show, a live palette whose last show relist was issued under 2 s ago is skipped (double toggle, or a relist still in flight under the 2 s `LIVE_RELIST_TIMEOUT`), and one with a `ttl` relists only once its rows are older than that; no `ttl` = every show, as before. Parallel relist and the 2 s timeout unchanged; skipped palettes are logged (`index\tshow relist\tskipped ...`).

### Extensions and protocol

- Extensions are TypeScript in one Bun host, UI as a render tree from a fixed component set, never HTML. Scripts/data files stay the zero-code tier under the built-in `scripts` extension (runs v1 script plugins and data palettes from a v1 config). Raycast API compatibility: nice to have; keep the component set close enough that a shim stays plausible.
- Manifest is `pal.json` next to `index.ts`, readable without running code (Settings lists an extension whose code fails; host sends the manifest with `extension/error`). Shape (`host/src/protocol.ts` `Manifest`): `name title description version icon author repo`, `settings: SettingSpec[]` (`[extensions.<name>]`), `palettes.<key>.{settings,ttl,title}` (`[palettes.<id>].settings`; title only a fallback while it fails). Settings come from the manifest only (9332904).
- Palette id in the file: the extension's name when the palette is named like it (`emoji`, `apps`), else `<extension>-<palette>` (`clipboard-history`); bare keys, `index::palette_id` resolves.
- Settings reach extensions resolved: core overlays file over manifest defaults (`Config::extension_settings`/`palette_settings`, one level deep, a set key replaces the default whole), pushes `settings/changed` before the first `list` and on every change; `settings.get()` reads it. Caller identity: host async context in `list`/`pick`, file on the stack at import, explicit argument elsewhere (Bun drops context through dynamic import). Changed values relist. `secret` settings arrive resolved (fcb967a).
- `list`/`pick`/`detail` take a trailing `ctx: { filter?, args?, refresh? }`; on the wire `filter`/`args` ride flat.
- Lazy detail: palette method `detail(id, ctx)`, meta `detail: "lazy"`; the open-with-pane flag is `showDetail`. UI asks after 100 ms cursor rest on an item without inline markdown (`Item.lazyDetail`), merges the reply over the inline one, skeleton only past 150 ms more, drops replies for a left item. Host caches per palette+id until relist/reload, UI per level until the index changes. `scripts` runs v1 `preview` there, `preview_max` (default 4): `prs` lists in ~40 ms instead of ~5.9 s, one `gh pr view` per rest (~1 s, cached).
- Filters through the core: `PaletteMeta.filters` via `sources()`; Search dropdown, Tab cycles, first is default (core sends `filter: filters[0].id` explicitly). Indexed palette listed per filter (`index::filter`), bucket swapped, each filter's list kept until relist; root sees the filtered bucket while inside, reset to the first on leaving, the next query restores it; the page asks per query and the core no-ops when the bucket already holds that filter. Input palettes get it per keystroke. Verified with `scripts/otp` (4), `ha-states` (10).
- Drill-in: `Effect.push { extension, palette, args? }` pushes a scoped level; with `args` it lists from the extension per keystroke (never the index) and picks are not remembered (frecency is the parent's). `Effect.show: Detail & { title? }` pushes a detail-only level (full width, crumb, Back on Enter/Escape, arrows/PageUp/Down scroll, input read-only). `scripts` maps v1 `{palette, env}` to `push` (env as args, re-exported to the script; rows kept per args so a root pick still works after a drill-in listing) and v1 `show` to `show`.
- `keep` relists an indexed palette (`index::pick`): "stay open and list again" holds for every palette; a closed window is gone next query.
- Live at the root: a `live` non-`input` palette (windows, otp) is indexed and relisted on every `pal://shown` (`index::on_shown`), all at once, 2 s each, one `pal://index`, spawned after the event: paint stayed 1-4 ms; relist ~15-20 ms windows, ~300 ms otp (reads the Messages db); a timeout keeps old rows. `windows` is plain `live` so titles are root results; `system` stays `input: true` (keep-awake row flips), so its rows are not at the root.
- Picks from live and input palettes are not remembered (edc1670).
- `ssh` and `processes` (v1's builtins `ssh`/`psg`) and `files` (mdfind / fd / locate / find) are real extensions (708abf7, c8f478f); the v1 rows under `scripts` for them are gone.
- Palette rows carry the extension title as subtitle (Raycast does), omitted when equal to the palette title (Windows / Windows). Root sections ordered by best hit.
- View level (third protocol pass, driven by `extensions/blackjack`): `Palette.view(ctx)` in place of `list` makes a view palette (`PaletteMeta.view = "view"`, reported `input: true` so the core indexes nothing and the root keeps its row), and `Effect.view` carries a `View { tree, actions, title?, id?, keys?: "actions" }`. The tree is a fixed vocabulary the app draws with the tokens (`ViewNode`: `stack`, `text`, `image` (`icon://` or `data:image/` only), `badge`, `divider`, `spacer`, `progress`, `keycap`), never HTML; unknown node types are skipped by the renderer, not thrown on. Keyed nodes get entrances/exits through the presence wrapper (`Transition { enter: fade|slide-up|flip, exit: fade|none, delay: 0..8 steps of --pal-dur-fast }`); a card is not a primitive, blackjack draws its cards as SVG data urls (`cards.ts`). The Launcher pushes a `{ kind: "view" }` level: no search input (the view's title in its place, `Search title=`), the footer keeps the first action and ⌘K, Escape/⌘⌫ pop, Enter/⌘Enter are actions 0/1, a modifier combo its action; with `keys: "actions"` a bare key (`h`, `space`, `+`, `up`) runs the action carrying it. A pick is `pick(view.id ?? "view", action, ctx)`; `{ view }` back replaces the level's tree in place (from a list row it pushes a level). The host checks every view (`host/src/view.ts`): `pal:` action ids refused, 2000 nodes / 24 deep, duplicate sibling keys. `docs/extensions.md`.
- Form level (`Effect.form`, driven by `extensions/quicklinks` and `extensions/snippets`): `Form { id?, title, fields: FormField[], submit: { id, title }, cancel?, errors? }`, fields `text|textarea|password|select|checkbox` with `label placeholder default required description`. The Launcher pushes `{ kind: "form" }` (the `Form` component in the body, the title in the search row as for a view, the submit in the footer, no ⌘K); Enter submits as `pick(form.id ?? row.id, submit.id, ctx)` with `ctx.values` (on the wire `values` rides flat beside `args`; `index::pick` takes `values: Option<Value>`), `required` is checked in the panel first (field marked and focused, no pick). A `{ form }` answer to the submit replaces the spec in place (the fields keep what was typed, `errors` show under them); any other answer pops the form first. `checkForm` in `host/src/view.ts` refuses empty/duplicate fields, unknown kinds, a `pal:` submit id, errors for no field. `stays_open` in effects.rs does not list `form` yet (only matters for a `copy` sent with a form: the HUD would say Copied). `ctxOf` now drops a `null` `args` (the core sends `args: null` for a plain level; extensions only ever truth-tested it). Vitest interaction tests run under `happy-dom` (added as a devDependency; per-file `@vitest-environment`, the others stay in node).
- Storage: `storage.get/set/remove/keys` in api.ts over `core/storage.*` (`pal_core::storage`, `app/src-tauri/src/storage.rs`): one JSON object per extension in `<data dir>/pal/storage/<extension>.json` (top-level data dir, shared across profiles like the clipboard db), atomic writes, 256 KB cap (a `set` over it rejects and rolls back), keys 1..128 bytes, extension name validated as a file name, a broken file set aside as `.bak`. Blackjack keeps its whole state there (shoe included, ~3 KB), so Escape mid-hand loses nothing.
- 9332904: process-group timeouts in scripts, stable bookmark ids, apps honour refresh, calc import guard, `home()`. 0b48368: extension `console.log` to stderr, non-array `list` is an error, symlinked roots. Linux `apps` (`.desktop`): `notes/linux.md`.
- Files "Open with…" and "Copy file" (`pal_core::apps`, `core/apps.{for_file,open_with}` via `app/src-tauri/src/apps.rs`; the `copy_files` effect in effects.rs over `clipboard::write_files`): `for_file` is `NSWorkspace URLsForApplicationsToOpenURL:` / `URLForApplicationToOpenURL:` on macOS (the documented replacement for `LSCopyApplicationURLsForURL` with `kLSRolesAll`, already reachable through objc2-app-kit's `NSWorkspace` feature, so no new crate; 39-44 ms on hornet for 7-10 apps) and, on Linux, `xdg-mime query filetype|default` plus the `mimeapps.list` (added/removed/default, `<desktop>-mimeapps.list` first) and `mimeinfo.cache` parsers (pure, fixture-tested on every platform), `text/*` also taking `text/plain`'s editors; `open_with` is `open -a` / `gio launch`. The extension pushes the same `files` palette with `args: { open_with: path }` rather than a second palette, so no "Open With" row appears at the root (the crumb and placeholder stay Files'); the level's rows are app paths with `{ app: path }` icons, the default tagged, and a level pick calls `open_with` then hides. `copy_files` writes through the same `platform::write(Content::Files)` the history's `copy` uses (arboard's `text/uri-list` on Linux; a backend without it is a failure toast, since the panel is still up). `.desktop` reading is now one place, `fs::desktop_dirs` / `fs::desktop_entry` (icons.rs and windows.rs used to carry their own). Open: `Effect.copy_files` and typed `apps.forFile`/`openWith` wrappers are not in `sdk/src/{protocol,api}.ts` yet (another agent owns them); the extension goes through `core.call` and the effect literal passes `tsc` only because `pick`'s return is a union of branch types, not a fresh literal against `Effect`.
- Bar items (`docs/design/bar.md`, 2026-09-16, spec only): extensions declare `bar.<id>` in the manifest and `Extension.bar[id].render(ctx) -> BarItem` in the code; one model (`icon title segments badge color urgent stale progress tooltip hidden menu`) rendered by three targets, the macOS menu bar (one Tauri tray icon per item, glyphs prerendered to template PNGs with `ab_glyph` from a bundled Nerd Font TTF since the NSStatusItem title is plain system-font text), sketchybar (batched CLI, names under `pal.` only, the owner's items untouched, `sketchybar --query bar` as detection) and a waybar JSON feed later. `hidden: true` is the owner's "earns its slot" rule and takes no space anywhere. Rich content is pal's own popover (a fourth NSPanel under the anchor rect: `TrayIconEvent::Click.rect` on the menu bar, `bounding_rects` from `sketchybar --query` on sketchybar) drawing a menu level (`menu: nodes`), a palette level or a view tree, the same on every target: popover only, no native NSMenu, since one renderer means parity across bars and one keyboard model and the native menu was the only per-target behaviour (it may return as an opt-in degradation, not a design path). Hover opens a peek after `[bar] hover_delay` (250 ms; `open_on_hover` on for sketchybar, off for the menu bar, per item overridable): non-activating, no keyboard, closes `hover_grace` (400 ms) after the pointer leaves item and popover; a click, the hotkey or any key engages it. Sources: `TrayIconEvent::{Enter, Leave}` and sketchybar `mouse.entered`/`mouse.exited` via `pal bar hover`. sketchybar popups and per-row click scripts are not reproduced. Pushes via `bar.update` over the reverse RPC; `[bar]` config with per-item target/position/hotkey; `pal bar` CLI for click scripts and scripting. Phases: the strip on both targets plus the popover with menu and palette levels, then the view level and hover, then Linux. Open calls listed in the spec (work hours as a pal notion, `target = "auto"` fallback, how a peek sees its engaging key).
- GitHub (`extensions/github`, 2026-09-16): one extension, five palettes (`prs`, `issues`, `repos`, `notifications`, `search`), replacing the v1 `repos`/`gh-reviews` scripts; the personal `prs`/`issues` scripts (sketchybar cache) stay under `scripts`. Not possible from an extension: an accessory on the palette's own root row (`PaletteMeta` has none), so the unread count is the first row of Notifications instead. Skipped: `$EDITOR` for Open in editor (a terminal editor cannot be launched from the panel; `code` else the folder), Checkout without gh (would need git in the extension), GraphQL ETags (the API sends none). ## Findings that changed the design

- Raycast 2.0 is a Rust core with a web UI in the system webview, the shape Tauri v2 gives; that set the go/no-go candidate (Shell, above).
- WebKit suspends rendering (rAF, timers) for a page whose window is ordered out or occluded, so the macOS panel is never ordered out (hidden = alpha 0, mouse ignored) and occlusion detection is switched off via the private `_setWindowOcclusionDetectionEnabled:` Raycast also flips. `app/src-tauri/src/panel/macos.rs:49`.
- `global-hotkey` 0.8 is X11-only on Linux; on Wayland the grab lives on Xwayland and fires only with an X11 client focused (0 of 7 from Chromium). Hence `pal toggle` over single-instance. `notes/linux.md`.
- First key after a re-show lost on WebKitGTK: hiding inside an unhandled keydown leaves a "forward next key" flag stuck. Rule: `preventDefault()` on the key that hides, never hide from an unhandled key event (`ui/keys.ts:110`). `notes/linux.md`.
- Pre-mapping at startup (show then hide, never on screen) took marko's first show from 111-124 ms to 12-20 ms; pre-painting took hornet's 706 ms to 1.7 ms release. `notes/linux.md`, 1db672e.
- The joined-haystack fuzzy match (fzf-for-js, nucleo par) ranks `hand` above the bookmark `ha` and drops Terminal.app from the `term` top 10; per-field weighting fixes it under 0.7 ms per keystroke. `notes/matching.md`.
- `!`, `^`, `'`, `$` are ordinary text in a query, not fzf operators (Spotlight and Raycast have none; a bookmark `!important` must be findable). `core/src/index.rs:263`, 75a7f47.
- Hotkey apply deadlock, found and fixed in d811024 (re-register order first touched in 75a7f47). `app/src-tauri/src/hotkey.rs`.
- WebKitGTK does no PUA font fallback: Nerd Font glyphs were tofu on Linux, so the font is bundled for that range. `notes/linux.md`.
- linuxdeploy exports `GDK_BACKEND=x11`, so the AppImage ran under Xwayland and the windowrule never matched; `main.rs` sets `wayland,x11` under `APPDIR`. `NO_STRIP=true` is load-bearing on Arch. `notes/linux.md`.
- CoreGraphics gives other apps' titles only with Screen Recording, so titles come from AX; AX returns nothing while the screen is locked, and lists only the current Space's windows, so an unmatched CG row is kept and focusing it activates the app (which switches Spaces); `kCGWindowName` lags AX, so matching is frame-first (`core/src/windows.rs`, commit 27d9873).
- Bun does not carry async context through a dynamic import; serde reports no spans for ignored keys. Both shaped the settings and diagnostics paths above.
- macOS accepts a `RegisterEventHotKey` for a combination Spotlight holds (`hotkey registered alt+Space` on hornet, where Spotlight is ⌥Space), and Spotlight still gets the press: the conflict has to come from reading `symbolichotkeys`, not from a refusal. Also: a binary launched from a terminal is Accessibility-trusted through the terminal (TCC's responsible process), so a scratch instance has to be an app bundle launched with `open` (`LSEnvironment` for `PAL_CONFIG`/`XDG_*`) to see a fresh machine's `permissions accessibility false`. And `TAURI_CONFIG` is a build-time input: set at runtime it does nothing and the binary hands over to the daily instance.
- The docs pass (06:30) found six code/doc contradictions (clipboard retention meaning, `exclude_apps = []`, `alias` semantics, unresolved `keychain:` in extension settings, cmd+w on Linux, deb tray dependency); all fixed in fcb967a, not papered over.
- Blackjack pass, limits found in the app/host and fixed there, not in the game: (1) no bare-key command in the grammar (a `keydown` for `h` was typing and went to the search input), so `keys.ts` gained `{ type: "key" }` that a handler may decline, and the ActionPanel, Form and Confirm claim it (`"native"`/swallow) so a game behind an overlay gets nothing; (2) the Launcher's `useKeys` returned early for any resolved command, which would have stopped typing from reaching the input once bare keys resolved, hence the `cmd.type !== "key"` fall-through; (3) fast key presses raced the host reply (two hits in flight, the second on a hand that may be over), so a view level runs one pick at a time and drops keys meanwhile (`viewBusy`), with the search sweep as feedback; (4) a late reply after Escape would have replaced whatever level was on top, so `Effect.view` is applied only when the view level it came from is still the top (`level` ref); (5) action ids could collide with the shell's `pal:*` and an item's actions could smuggle extra fields, so the host refuses `pal:` ids in a view and `toAction` keeps the five wire fields only; (6) `shortcutKeys("+")` split on its own key and drew two empty caps, so a trailing `+` is the plus key; (7) `+`/`-`/`space`/arrows had no shortcut spelling, now `keyName` gives `space`/`up`/`down`/`left`/`right` and format.ts draws them on both platforms; (8) nothing focusable in a view level (no input), so the `.pal-view` document takes focus (`autoFocus`) and the input is refocused on leaving; (9) a gallery with two window-scoped Launchers answered every key twice (two action panels opened on ⌘K): one live launcher at a time there (`LiveSlot`), the app has one anyway; (10) a keyed child leaving a flex row needs its exit to finish before the DOM goes, so `Presence` gained `onExited` and `View` keeps leaving children at their old index under it; a row whose children come and go holds its height with `minHeight`. Not hit: the 5 s bridge timeout (a storage call is well under a millisecond) and tree size (a full table is ~25 nodes and ~20 KB with the SVG cards; the cap is 2000).
- Home Assistant extension (2026-09-16, replaces the v1 `ha-states`/`ha-services` scripts): (1) the entity palette is `live` with no `ttl`, so every show is one `/api/states` (385 KB, ~0.5 s over Cloudflare on the owner's setup); that is the cost of a current state at the root and what the owner had. (2) Areas come from one `/api/template` render (`areas()`/`area_entities()`/`area_name()`, 0.75 s, 164 of 507 entities mapped), cached ten minutes; the entity registry over the websocket was the heavy alternative. (3) HA's REST `/api/services` carries `name`/`description` for almost no core service (10 of 274 on the owner's HA; they live in frontend translations), so the form labels are the title-cased keys and the `example` is the placeholder; `selector` decides the field kind. (4) "Lights tinted when on": the wire has no tint for a glyph, only a hex colour that draws a dot, so an `on` light is a dot in its `rgb_color` (warm white without one) and an `off` one the bulb glyph. (5) Bun's `fetch` drops `Authorization` when a redirect changes the origin, and the owner's `HA_SERVER` is `http://` behind Cloudflare which answers 301 to `https://` for a non-curl user agent, so a valid token read as 401 until the client followed redirects by hand (one hop, token kept, logged once). Set the `https://` URL in pal. (6) The live check ran read-only plus `persistent_notification.create` and `dismiss` through the service form: all ten `input_boolean`s on the owner's HA are AC control flags and every scene sets lights, so nothing there was a harmless toggle.

## otp, onepassword, browser-tabs (2026-09-16)

Three first-class extensions replacing the v1 script palettes `otp`, `op` and `tabs` (`extensions/{otp,onepassword,browser-tabs}/`, docs in `docs/palettes.md`).

- `otp` reads `~/Library/Messages/chat.db` itself over `bun:sqlite` (read-only) rather than the `datak` view v1 curled: the generic product cannot depend on a personal service. Full Disk Access is the whole permission story: SQLite answers `SQLITE_AUTH` ("authorization denied") and `cp` answers EPERM for a process without it (verified from the agent shell on hornet, which has none), so the palette's one hint row opens the `Privacy_AllFiles` pane. A locked database is copied with `-wal`/`-shm` and read from the copy. Since Ventura `message.text` is often NULL and the text sits in `attributedBody` (a typedstream: the string after `NSString`, five framing bytes, a 1/3/5-byte length), decoded in `bodyText`. A code is only taken from a message that names one (a keyword list across English, Turkish, Spanish; suffixes allowed, prefixes not, so `decode` does not count) and is a 4..8 digit run not inside an amount, date, time or phone number; the candidate nearest a keyword wins, 6 digits breaking ties; `G-123456` yields its digits, which is what Google's form takes. Numbers and emails resolve to names through the AddressBook databases (same permission), best effort. Not carried over from v1: the hand-kept sender table with per-bank icons and the money/shop/gov filter; the sender string and a green code tag are enough to identify a row.
- `onepassword` wraps `op` with a `ttl` cache of `op item list` so the per-vault filters and a refresh inside the ttl do not re-run the CLI (and its Touch ID prompt). Secrets are fetched only on a pick (`op item get <id> --fields label=<f> --reveal`, `--otp`) and go straight to `copy`; nothing secret is in a row, the index or a log. "Open in 1Password" is `onepassword://view-item?i=&v=&a=`, not an `op://` url: `op://vault/item/field` is the CLI's secret-reference scheme, while the app registers only `onepassword` and `onepassword8` (`/Applications/1Password.app/Contents/Info.plist`, `CFBundleURLTypes`). Filters come from the `vaults` setting at load, since `PaletteMeta.filters` is static; a change lands at the next host start (documented). Signed out and "no accounts configured" are one hint row; hornet has the CLI (2.39.0) with no account configured, which is the state that was verified live. `op` is looked up on PATH, then the installers' directories, since the app under launchd has a bare PATH.
- `browser-tabs` speaks CDP itself (`cdp.ts`: `/json`, `/json/version`, `/json/activate`, `/json/close`, and one browser WebSocket with id-multiplexed calls so the per-page media probe and window lookup run concurrently: 10 tabs probed in 5 ms on hornet's daily Chrome, the whole listing 83 ms) instead of shelling to `bt`, which is Cagdas's tool, not the product's. Safari and a Chrome without the port go through one `osascript -l JavaScript` run per listing (288 ms for 10 Chrome tabs); a Chromium app already on the port is skipped so tabs do not list twice. Firefox is read from `recovery.jsonlz4` (mozlz4: magic, LE size, one LZ4 block; decoder in `lz4Block`) and is read-only, so only its window can be focused. Focus is the browser-side select (`/json/activate` + `Page.bringToFront`, or `activeTabIndex`/`currentTab` + `index = 1`) followed by the `focus` effect on the OS window from `windows.list` whose title matches the tab's, else the browser's front window, so the panel hides first. Mute is the media-element mute `bt` does (`e.muted = true` on every `video`/`audio`), not Chrome's tab mute, which CDP has no call for without a helper extension; `bt`'s unpacked-extension trick was not ported. The Automation refusal (-1743) is a hint row opening the `Privacy_Automation` pane. Verified live on hornet read-only: the CDP listing of the daily Chrome and the AppleScript listing of the same tabs with the port setting pointed elsewhere; nothing was focused or closed.

## calc rebuilt (2026-09-16)

- `calc` was mathjs over the query and could not do `12 usd to try`. Rebuilt around three parsers tried in order (`extensions/calc/{dates,currency,math}.ts`, `index.ts` the orchestration, `format.ts` the numbers, `row.ts` the shape they answer): dates and time zones first (their keywords are unambiguous), currency second (a currency token on the right or the left), mathjs last with a rewrite pass for the idioms it lacks (`sqrt 2`, `15% of 240`, `240 + 15%` = 276, `72 f to c`, `12 gb to mb`, `100 kph to mph`, `5 ft 3 in`, `3 x 4`, `2 power 10`, `10 mod 3`). mathjs stays for arithmetic and units: its unit table is good, only the spellings were missing (`kb` there is a kilobit, so the byte aliases map to `kB`/`MB`/`GB`; `f`/`c`/`k` are degrees only across a `to`).
- Rates: the ECB reference set through frankfurter (`https://api.frankfurter.dev/v1/latest`; `api.frankfurter.app` now 301s there). Free, no key, 30 currencies, TRY included, no crypto (so `1 btc` lists nothing rather than fetching a second source; no `rate_source` setting until one exists). Fetched lazily on the first currency query, never at load; kept in `storage` under `rates` (`{ base, date, rates, fetched }`, ~1 KB, the one exception to "storage is not a cache") and refreshed after 24 h in the background: `ensureRates` awaits only the one storage read, the fetch is a module-level promise nobody awaits, so the first query without a cache answers an inert `Fetching exchange rates…` row and the next keystroke has the numbers. A stale or offline set answers dated (`rates 2026-09-15` accessory). A failed fetch backs off a minute. `PAL_CALC_OFFLINE=1` (tests, or a machine that should never call out) and `PAL_CALC_RATES_URL` (the test's Bun server) are the two env knobs.
- Rows: the result is the title (Enter copies it as shown), the query as understood the subtitle (`12 USD to TRY`), accessories the rate and date / the unit; a second row when there is another form: the other bases for a number typed as one or a bare integer (not for every integer result, `2+2` stays one row), a fraction, the reverse conversion, the ISO date, the unix time. Row ids are fixed (`result`, `base`, `fraction`, `reverse`, `iso`, `unix`) and `pick` reads the last listing from a map: an input palette relists per keystroke and the ids only need to be stable across those. Actions: Copy result, Paste result (`paste: { text }`), Copy without formatting (`cmd+shift+c`, `583.68` / `1000000`), Copy expression = result (`cmd+shift+e`).
- Silence while typing: every parser returns nothing for a query that does not parse, so no error rows; two exceptions on purpose: a target still being typed (`12 usd to tr`) keeps the source's row (a prefix of a known currency word), and a date-shaped query that is no date (`2026-02-30`) lists nothing instead of falling through to `2026-2-30 = 1994`.
- Formatting through `Intl`: `precision` (default 10, was 14) is significant digits for the fraction only, integers are never rounded (`maximumSignificantDigits` would print `2^40` as `1,099,510,000,000`); units and rates cap at 6 (`22.2222 °C`, not `22.222222222222`). `locale` (default `en`) drives grouping, the decimal separator and dates, and is applied to the input too (`1,5 + 2` under `tr`). `home_currency` empty means the time zone's currency (`Europe/Istanbul` is TRY; the Intl locale is `en-US` under a `LANG=en_US` shell even on an `en_TR` Mac, so the zone is the better signal), then the locale region, then USD.
- Zones: an alias table (abbreviations, ~120 cities and countries) over IANA ids, `utc+3` as `Etc/GMT-3` (whole hours only: no `Etc` zone has minutes), wall-clock to instant by two `Intl.formatToParts` offsets. `ist` is Istanbul (the airport code, and where the machine is), India by name; `cet` follows Berlin's DST. Without a source zone the local one; the time is today's in the source zone; `next day` accessory when the date differs.
- Tests: `host/test/extensions/calc.test.ts`, 23 tests, 168 expects, ~0.8 s: every doc example through the harness with canned rates (seeded through the harness's `stored` map before the host starts, `PAL_CALC_OFFLINE=1`), `process.env.TZ = "UTC"` so the spawned host agrees with bun test's own UTC, and two more hosts against a `Bun.serve` for the no-cache (fetching row, stored set) and stale-cache (dated answer, background refresh) paths.

- The core drops a pick unanswered after 10 s (`app/src-tauri/src/host.rs` `REQUEST_TIMEOUT`), which `docker stop` on a process that ignores SIGTERM (docker kills at 10 s) and `compose up` walk straight into. Every action in these three extensions waits at most 8 s (`WAIT_MS`) and then answers a "not done yet" toast while the command goes on (`proc.unref()`, still killed at its own longer limit); the palette lists again on the next show. Make's background mode is the same rule, so its planned `timeout` setting was dropped: nothing above 8 s could ever be honoured.
- Logs are a `show` level (a code fence of the last 200 lines) as specified, but a `show` level has no Refresh: the shell offers `pal:refresh` (⌘R) only at the root and on an indexed palette level (`app/src/Launcher.tsx`, the `actions` memo). Re-picking Logs re-reads. A `view` level would carry a ⌘R action of its own but scrolls only by wheel (no keyboard scroll for a view), which is worse for a tail. Open: a refresh hook for `show` (a `pick` id the shell re-asks on ⌘R).
- `services` picks its backend by platform (`PAL_SERVICES_BACKEND` forces one for the tests). systemd: `systemctl list-units --type=service --all --output=json` (systemd 245+; marko has 261) merged with `list-unit-files` so a disabled unit that never ran still lists; templates, masked and alias files skipped; an instance's enabled state is its template's. A system verb goes `systemctl --no-ask-password`, then `sudo -n`, then `pkexec`, each tried only when the previous was a permission refusal, and a toast quotes all three when none is allowed (verified on marko from the agent shell, where `sudo -n` has no window and `pkexec` has no agent: `alsa-state.service` start refused three ways, nothing changed). A user unit created for the check (`pal-live-test.service`) went through start, logs, restart, enable, disable, stop and was removed after. launchd: `launchctl list` for state, the plists in `agent_dirs` for the rows (a setting rather than a hard-coded pair so the tests point it at a temp folder), `bootstrap`/`bootout gui/$UID`, `kickstart -k`; `application.*` launch jobs are dropped from the Loaded and Running filters (568 rows on hornet, most of them those). Verified on hornet read-only: 16 agent rows across the two folders with the right pids (yabai, skhd, sketchybar, syncthing running; `io.cagdas.pal` not loaded since the app is started by hand).
- `make` walks the `projects` roots itself (depth 2, `readdirSync`) rather than shelling to the owner's `mk` (which is `rg --files -g Makefile` over `~` and `~/proj`, a personal tool). Targets are parsed from the text: `^names:` not followed by `=`, names with `%` or `$` or a leading dot dropped, `.PHONY` names added when no literal rule exists, description from `## text` on the line or the comment line above (the owner's Makefiles use `# comment` above `.PHONY:` + target, so a plain `#` counts and the `.PHONY` line is skipped when looking up). Run wraps the command in `sh -c 'make t; …; read -r _'` so the terminal window survives a quick target (v1 ran in the background and showed long output in a `show`, which the `background` terminal setting keeps). Listing `~/proj` on hornet: 69 targets in 9 projects.
- The terminal launcher is a copy of the ssh extension's (`extensions/{docker,make}/terminal.ts`, identical files), with shell quoting for the AppleScript terminals and a `cwd` (a `cd` in front). A bundled extension may not import a sibling's file (each installs on its own), so the copy stays until `@zcag/pal` grows a terminal helper; that is the place for it, and ssh should then use it too.
- Tests through the harness with fake binaries first on PATH (`host/test/extensions/{docker,services,make}.test.ts`): a `docker` shell script with canned rows, a mode file for "daemon down" and a 12 s `stop` for the pending path (11 tests, one of them 8 s); `systemctl`/`journalctl`/`sudo`/`pkexec` scripts with an `allow` file choosing which escalation works, and `launchctl` plus a temp LaunchAgents tree, both backends in one file (13); a temp projects tree with three Makefile spellings, a too-deep folder and a `node_modules` one, the real `make` for the background path (8). 32 in all. `PAL_TERMINAL_LOG` makes `openTerminal` append the argv to a file instead of spawning.

## Reference extensions: unicode, colors, icons, network (2026-09-16)

The four v1 data palettes (`chars`, `colors`, `icons`/`nerd`, `ip`) became bundled extensions; what was decided along the way:

- **Grids carry `section` on the row and the core keeps runs together**, so a block or a set is one header in the grid. The three reference grids put a "Recent" section first from the extension's storage (the last twelve picks) and drop those rows from their block, since an id may appear once per palette. The core's frecency also lifts a picked tile at the empty query, so between listings a used tile sits at the top under its block's header; the Recent section catches up at the next listing (start, ⌘R). Accepted rather than re-listing on every pick (`keep` would hold the panel open after a copy).
- **Generated tables, committed, with the script beside them.** `unicode/build.ts` (UCD names + WHATWG entities over curated ranges, 1795 rows, 160 KB), `colors/build.ts` (CSS names from `color.ts`, pal tokens read out of `tokens.css`, Tailwind and Material from unpkg, 700 rows, 48 KB), `icons/build.ts` (`glyphnames.json` at the pinned Nerd Fonts release, 10995 glyphs, 282 KB). No fetch at runtime, no UCD in the bundle. The icons listing is ~3.4 MB of JSON per start (11k rows with four actions each) and has no `ttl` so Recent stays fresh; the rows were trimmed to name, code point subtitle and one keyword. If the start-up pass ever shows in the profile, a `ttl` of a day is the knob.
- **Swatch tiles are `{ image: <svg data url> }`**: with `mask: rounded` an image icon fills the tile box, which nothing else in the icon vocabulary does (a hex icon draws a dot). The same data url in the detail's markdown gives the wide swatch; marked only blocks `data:` on links, not images. Unicode's detail draws its big glyph the same way (an SVG `<text>` in a mid grey, `#85869A`, that reads on both themes); Nerd Font glyphs cannot, since an `<img>` SVG cannot use the page's `@font-face`.
- **Colour maths is a dependency-free module** (`colors/color.ts`): parse, sRGB/HSL/HWB/OKLab/OKLCH, WCAG contrast, nearest CSS name in OKLab. Unit-tested directly by importing the file; the harness tests cover the palettes. Pick-from-screen was not built: no core capability samples the screen, and the doc says so rather than shipping a stub.
- **Network rows put the value in the name** (v1 put it in a tag): a list of addresses reads better with the address as the title and the label under it, and the name is what the search matches. Live with `ttl: 60`, so a show relists only when the rows are a minute old; the public IP is one fetch cached ten minutes in the extension, dropped by the shell's Refresh (`ctx.refresh`). Every tool runs with a 3 s timeout and a missing one is silently absent. A pick or detail for an id the extension has not listed (the restored cache after a restart) gathers once more instead of failing. The tunnel interface duplicating the Tailscale addresses is folded away.
- **Skipped, and why**: Flush DNS (sudo, no way to prompt from the host), pick colour from screen (no capability), the big Nerd Font glyph in the detail pane (font reach), v1's wider freedesktop name list (only the SDK's 114 names draw). The macOS SSID is redacted for a process without Location Services (`ipconfig getsummary` says `<redacted>`, `system_profiler` too, verified on hornet); the row is labelled by kind and the detail says why.
- Tests fake the OS with shell scripts on PATH (`fakeBin`) and `PAL_NETWORK_OS` / `PAL_NETWORK_RESOLV` to run the Linux path on a Mac, and a `Bun.serve` on port 0 as the public IP endpoint, counting hits to prove the cache.

## audio, bluetooth, wifi, media (2026-09-16)

Four device capabilities in the core (`pal_core::{audio,bluetooth,wifi,media}`, bridged as `core/audio.*`, `core/bluetooth.*`, `core/wifi.*`, `core/media.*` in `app/src-tauri/src/{audio,bluetooth,wifi,media}.rs`, typed in `sdk/src/api.ts` at the end) and the palettes over them (`extensions/{audio,bluetooth,wifi,media}/`, replacing v1's `audio`, `ble`, `wifi`, `media` script palettes; docs in `docs/palettes.md`). The four modules share one shell-out helper, `pal_core::tool` (`run`, `run_in` for stdin, `run_timeout` through coreutils' `timeout` on Linux, `osascript`), with one `Error` (`Unavailable` / `Failed` / `Io`) each re-exports; the older copies of that helper in `system.rs`, `apps.rs` and `windows.rs` were left where they are (other agents were in those files this round) and are a follow-up to fold into `tool`.

- **audio**: macOS is the CoreAudio HAL in-process through `objc2-core-audio` (`AudioObjectGetPropertyData` on the system object and each device; `std` + `AudioHardware` features only), no tool to install: the UID is the id, a device is an output or an input by which scope has streams, the volume is the virtual main volume (`'vmvc'`, `kAudioHardwareServiceDeviceProperty_VirtualMainVolume`, which the crate does not carry so it is a local constant) with the per-channel scalar on elements 1 and 2 as the fallback, mute is `kAudioDevicePropertyMute` on the main element, and the default is set on the system object. Verified read-only on hornet: 2 outputs (the Bluetooth speaker at 25%, the built-in speakers at 56% default) and the built-in mic at 57%. Linux is `wpctl status` parsed (the `*` in the gutter is the default, `[vol: 0.40 MUTED]` the rest) with `wpctl set-default|set-volume|set-mute`, else `pactl -f json list sinks|sources` + `get-default-sink|source`; verified on marko (3 devices, mute toggled twice on the non-default HDMI sink and read back). The palette pushes itself with `args: { volume: <row> }` for the 0/25/50/75/100 presets rather than a second palette.
- **bluetooth**: macOS lists from `system_profiler SPBluetoothDataType -json` (80 ms on hornet, and the only unprivileged source that has the device type and the battery levels, AirPods' left/right/case included; `blueutil --paired --format json` has neither) and connects/disconnects through `objc2-io-bluetooth` (`IOBluetoothDevice deviceWithAddressString:` then `openConnection`/`closeConnection`, which is what `blueutil` calls), so `blueutil` is not needed at all and there is no hint row for it. Verified read-only on hornet: 9 paired, 2 connected, kinds right (speaker, mouse, headphones, keyboard, gamepad); no device was connected or disconnected. Linux is `bluetoothctl devices Paired` (falling back to `paired-devices` for BlueZ before 5.65) plus `info` per device, every call under `timeout 5` (`connect` 20) and gated on `/sys/class/bluetooth` having an adapter, since without one `bluetoothctl` blocks rather than answering empty (v1's finding); on marko, which has none, that is the `no Bluetooth adapter` row.
- **wifi**: macOS is `networksetup` for the interface, the radio, the preferred list, join, forget; `scutil` (`State:/Network/Interface/en0/AirPort`) and `ipconfig getsummary` for the current link; `security find-generic-password -wa` for a password; `system_profiler SPAirPortDataType -json` for a scan, which takes 9.2 s on hornet, so the core caches a scan for 60 s and `scan` takes a mode (`cached` never runs it, `auto` reuses under the TTL, `fresh`): the palette lists Available from the cache on macOS with a Scan row, and with `auto` on Linux where `nmcli device wifi list` answers from NetworkManager's own cache. Linux is `nmcli -t` throughout, with the `\:` unescaping done once (`nmcli_fields`). Verified read-only on hornet (interface en0, powered, current link on channel 44 with the IP and WPA2_PSK, 90 preferred networks) and on marko (no Wi-Fi interface: the one row). Join, forget, power and the keychain prompt were not exercised on hornet (they change his network); the fixture tests cover the parsers and the extension's flows.
- **media**: macOS asks Spotify and Music over `osascript` only after `NSRunningApplication` says the app runs (a `tell application` to one that does not would launch it: the check is load-bearing), the script returning one line joined with `character id 31`; Spotify gives the artwork url and the `spotify:track:` url, Music neither. `nowplaying-cli` on PATH is one more row (`system`) for any other player, and `NowPlaying.system_wide` tells the palette whether to hint at installing it. Linux is `playerctl -l` then `metadata --format` per player with the same separator, units 1e-6 (MPRIS microseconds) against Spotify's 1e-3. Neither Spotify nor Music was running on hornet and no player on marko, so the live rows were not seen; the parsers are fixture-tested (Spotify, Music, playerctl and nowplaying-cli lines) and the running-check path was exercised (nothing launched).
- Tests: 22 core `#[test]`s on fixtures (`wpctl status`, `pactl` JSON, `system_profiler` Bluetooth and AirPort JSON, `bluetoothctl` list and info, `nmcli -t` lines, `ipconfig`/`scutil`/`networksetup` text, the player lines, `tool`), run on hornet and marko; 26 harness tests across `host/test/extensions/{audio,bluetooth,wifi,media}.test.ts` with canned core replies, run on both (the wifi and media tests assert per `process.platform` where the palettes differ). `core/examples/devices.rs` is the terminal check for a machine.

## Raycast parity pass on the bundled extensions (2026-09-16)

- **apps**: a `Running` tag on an indexed palette is only as fresh as the last listing; `live` was rejected because it drops frecency ranking, which apps need most. Quit and Hide drop the scan cache and answer `keep`, so the tag follows those two at least. Quit is `osascript quit` (graceful) with a `SIGTERM` fallback, guarded by a `ps` check so a not-running app is never launched by the AppleScript. System Settings panes are a curated table of 35 ids: `/System/Library/ExtensionKit/Extensions` mixes panes with intents and widgets and has no display names. Localised app names are not read (binary `InfoPlist.strings`, a spawn per app). A pre-existing `!seen.add(...)` (always false) let same-named apps repeat across roots; fixed to `has` + `add`.
- **bookmarks**: Safari's plist is read as XML through `plutil -convert xml1` and a 50-line plist reader (`sources.ts`), not `-convert json`: JSON conversion refuses `<date>`/`<data>` values and the Reading List has dates. No npm dependency (a `bplist-parser` would have meant a lockfile per extension for one file). Firefox is `bun:sqlite` over a copy of `places.sqlite`, deleted after. `PAL_BOOKMARKS_HOME` points the profile roots at a temp home for the tests, like `PAL_FILES_BACKEND`. Duplicate urls are folded (first source wins) instead of the old NUL-ordinal ids.
- **emoji**: `live` + `ttl: 30` rather than indexed: a "Recently used" section needs the extension's own order, and an indexed palette re-lists only on start/`⌘R`/settings, so a just-used emoji would have hoisted its whole category above the recents until the next start (sections are contiguous in order of first appearance). The cost is one 1906-row listing per show at most every 30 s and no frecency boost on emoji at the root. `data.json` annotated from unicode-emoji-json (`group`, `skin_tone_support`) joined on the glyph; the names and keywords stayed emojilib's.
- **clipboard**: Links and Colors are text entries narrowed on this side (the core knows three kinds); "Delete all unpinned" deletes one by one over pages because the core's only bulk operation is `clear`. A colour's icon is the hex string, which the UI already draws as a tinted dot.
- **files**: recents come from `mdfind -attr kMDItemLastUsedDate` (sortable, unlike plain `mdfind`) or `recently-used.xbel`; `PAL_RECENT_XBEL` lets the tests feed the xbel path on macOS too. The empty query of the Files palette shows them in place of the hints (Raycast's empty state); `recent` is a second palette in the same extension sharing rows, actions and detail.
- **processes**: `:port` is a query mode inside the palette rather than a filter, so a port can be typed; `ss` first, else `lsof -F pcn` (field output, since the table form truncates commands). "Open in Activity Monitor" types the pid through System Events (there is no URL scheme); best effort.
- **ssh**: the section is the file the host came from; `ping -c 1` with `-W` in ms on macOS and seconds on Linux.
- **quicklinks/snippets**: import/export is a form with a path field; `{selection}` maps to the clipboard, `{cursor}` documented as unsupported (pal pastes whole).
- Tag colours are token names only (`amber` replaced processes' `orange`).
- Docs for this pass are an appended section of `docs/palettes.md` (the earlier per-palette sections were left as they were, by the brief); the tests are `host/test/extensions/*.test.ts`, every new pure module (`apps/desktop.ts`, `bookmarks/sources.ts`, `emoji/skin.ts`, `files/recent.ts`, `processes/ports.ts`) tested without a host.
