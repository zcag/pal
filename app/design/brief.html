A launcher you see for two seconds, four hundred times a day.

pal appears over whatever you were doing, takes a few keystrokes, and leaves. Its visual job is to be legible instantly and to never draw attention to itself. This page is the design system for that: every value below is the real token, rendered by the real component styles, in both themes. Nothing here is a picture of the design; it is the design.

The one thing that is ours: a single left edge. The query you type, every row title, and the detail heading all start at the same 52px line, so the eye lands once and never re-aligns. Everything else (a cool-graphite neutral, an iris accent used only where interaction lives, an amber highlighter for what matched) is chosen to keep that edge quiet.

The panel at rest

720 by 440, radius 14, no visible border: the edge is a 1px shadow ring plus a 1px inner highlight along the top, so the panel reads as a solid slab sitting on the desktop rather than an outlined box. Over a wallpaper the surface is glass (84% light, 80% dark, 40px blur); on a compositor that cannot blur, --pal-bg is the opaque fallback and nothing else changes.

Light. Glass over a wallpaper: the blur is what keeps text legible over anything.

Dark. Same geometry, same rows; only tokens change.

Why not 750 by 475. Ours is 720 by 440 so it fits a 1280-wide display with 280px to spare on each side and every edge lands on the 4px grid (180 by 110 units). The list shows eight rows and a fraction: the cut row is the scroll affordance, so no scrollbar is shown until the pointer enters the list.

Why no accent on the selected row. Selection moves on every key repeat. A neutral 7% tint (9% in dark) is visible at a glance and never competes with the accent, which is reserved for the caret, focus rings, links and the primary button.

Geometry and the spacing grid

Base unit 4px. Every height, inset and gap is a multiple of it. Two vertical edges organise the panel: the icon edge at 16px (search glyph, row icons, section headers, footer) and the text edge at 52px (query text, row titles, detail heading). 52 = 16 padding + 24 icon box + 12 gap in the search row, and 8 list inset + 8 row padding + 24 + 12 in a row: two different paths to the same line.

Type

The system UI font, nothing bundled: SF on macOS, the desktop's sans on Linux; the system mono for code and codes. The panel is judged next to Spotlight and Raycast on a Mac, and both are set in SF; a bundled face (IBM Plex was the candidate) reads as a web page dropped onto the desktop, and costs a font load before the first paint. On Linux the stack falls through to what the desktop set (Inter, Noto Sans, then system-ui), so pal looks like the rest of that desktop rather than like a Mac; the same row measuring a few percent wider there is the price, and the layout (ellipsis on titles, fixed accessory column) absorbs it. What Plex was chosen for, true tabular figures, comes from the system font instead: accessories, tags and metadata values set font-variant-numeric: tabular-nums, so dates, sizes and OTP codes still line up across rows. Three weights only: 400, 500, 600.

Scale is five sizes, chosen for the row they sit on rather than a ratio: 11 / 12 / 13 / 15 / 18. UI text is single-line and vertically centred, so its line height is 1.25; prose in the detail pane gets 1.55. Tracking is default everywhere except +0.01em on 11px labels, where a text face tightens.

Stacks, from tokens.css: --pal-font-ui: -apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI", "Inter", "Noto Sans", system-ui, sans-serif and --pal-font-mono: ui-monospace, "SF Mono", Menlo, "JetBrains Mono", monospace.

What is deliberately absent. No all-caps labels (section headers are 11px medium, sentence case, in the faint colour). No weight change on selection (a bolder selected title shifts the text by a pixel on every arrow key). No italic anywhere in the shell.

Colour

Both themes are first-class; neither is derived from the other. The neutrals are graphite with a trace of blue (#1A1A1F, not #111) so they sit with the iris accent instead of fighting it. Text is three levels: fg for titles and prose, muted for subtitles and accessories, faint for placeholders, section headers and footer hints. Faint is only ever set on --pal-bg; on elevated or sunken surfaces secondary text uses muted, which is why every listed pair passes AA.

The accent is iris: it marks the caret, focus rings, links, the primary button and the loading sweep, and nothing else. The match highlight is a separate hue, an amber highlighter behind the matched characters, so "this is what you typed" and "this is interactive" never share a colour. Tags get eight muted hues with opaque tint backgrounds, so they look the same on a selected row as on a plain one.

Iconography

One 24px box, always. What changes is how each kind sits inside it, so a list mixing apps, emoji, favicons and glyphs still has one optical column.

The brand palette, --pal-brand-*: twelve colours, one light and one dark value each, picked so a white mark reads on every one in both themes. An extension names the one it is known by; the neutral family (apps, windows, files, processes, services, system, scripts) is slate.

  • App icons fill the box at 24px, unmasked. macOS icons carry their own shape and Linux icons are inconsistent; a mask would cut the first and not fix the second. Rendered here as placeholders; the app draws the real artwork.
  • Monochrome glyphs are 16px, 1.5px stroke, round caps, centred. Tinted --pal-fg-muted, and --pal-fg on the selected row so the icon lights up with the title.
  • Icon tiles are the extension's own icon: a rounded square in one of the twelve brand colours below with a white mark, one Nerd Font glyph at 62% of the side or an SVG path at 66%. The side follows the box (24 in a row, 20 in the crumb and the footer, 32 in a grid cell, 56 on a settings page) and the radius is a quarter of it, so every size is the same shape; a hairline inset ring (--pal-tile-ring) keeps ink a square on the dark panel. Selection changes nothing on a tile, as on an app icon. Every palette of an extension wears the tile at the root, so the root reads as a grid of marks, like Raycast's.
  • Tinted glyphs are a row's mark in a colour: a plain Nerd Font glyph takes its palette's tile colour (so an extension's rows are marked in its colour, never grey next to a tile), a state keeps its own (an open pull request's octicon in green, a merged one in violet). Ink-tinted glyphs draw in the text colour instead, since ink vanishes on the dark panel. Glyphs listed as content (a catalog, a grid) are not tinted. The tint holds on the selected row.
  • Emoji render at 17px in the platform colour font, no background. 17 matches the optical weight of a 16px stroke glyph.
  • Favicons are 16px with a 3px corner mask, centred in the box. Sixteen is what sites ship; scaling them up shows the pixels. Missing favicon: the globe glyph.
  • Colour swatches are 18px circles with a 1px inner ring, so white and near-background colours still show an edge.
  • Avatars are 22px circles: one pixel of air inside the box keeps a round shape from looking larger than a square one.

Motion

A launcher is judged by the gap between the hotkey and the first painted frame. So the show is instant: no scale, no fade, the panel is simply there. Motion is spent only where something needs continuity: things leaving, things opening over other things, and the status line. Everything that responds to a key repeat never animates.

Reduced motion. prefers-reduced-motion sets every duration to 0; the states are still all reachable, just without the in-betweens.

States

Each state below is rendered live in the page's current theme (switch it in the header). Content is real: the apps on this machine, bookmarks with favicons, an OTP code, a GitHub pull request with its markdown body.

Root search, sections and accessories

Empty query. Sections are the palettes that contributed rows. Accessories, right-aligned: a code with its countdown, a tag with a date, a date, plain text, a tag. The cut row at the bottom is the scroll affordance.

A query, with match highlighting

Typing gra. Matched characters get the amber highlighter, in the title and the subtitle. Selection is the neutral pill; the footer names the primary action for that row.

Detail pane

Inside the GitHub palette (the crumb in the search row says where you are). List narrows to 296, subtitles hide, the pane shows rendered markdown with a metadata block pinned to its bottom.

Action panel

Opens from ⌘K over the list, anchored bottom-right at its footer hint. The list dims under a scrim; the search row stays as is so you keep your place. Destructive actions are red and always last.

Prompt

A question with two answers. The safe one is esc, the committing one is ↵, and the destructive one is red so the colour matches the action list.

Form

Labels right-aligned to a 112px column so fields share a left edge. The focused field lifts to the elevated surface with the accent ring. Submit lives in the footer, like every other primary action.

Grid view

Eight 80px cells per row, four rows, 56px tiles, captions below. Emoji sit on the sunken tile; colours fill it with a 1px inner ring.

Empty

Says what was searched, then what to do. The footer still offers the fallbacks so the keys are learnable.

Loading, rows streaming in

The sweep under the search row says more is coming; rows already received are shown and selectable. No skeletons: a skeleton is a promise about layout that streaming cannot keep.

Error

What failed and why, in the interface's voice, with the next step on a key.

Toast

Toasts take over the footer's context slot rather than floating over content. Success, failure and in-progress variants.

HUD

After the panel hides, for actions that would otherwise be silent. Bottom-centre of the screen, one line, gone in about a second.

Tokens

Everything in app/src/ui/tokens.css, with its current value in each theme (read from the live stylesheet) and what it is for. Dark follows the OS unless <html data-theme="light|dark"> pins it.
